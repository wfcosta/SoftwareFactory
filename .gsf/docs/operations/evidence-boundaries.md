# Evidence boundaries and finite review budgets

## Purpose and authority

Use this reference when reviewing provider evidence, package custody, MCP ingress, worker observations, checkpoints or memory changes. It preserves the finite boundaries of the retired auxiliary implementation as **review information**, not an installed runtime, new policy profile, execution gate or automatic validator. Work stays in this repository as Markdown; do not create another repository, generator, parser, server or wrapper to make a missing control appear available.

The accepted product policy, exact task and actual native tool/version determine permitted effects and effective limits. Do not silently adopt a legacy default as authority, weaken an accepted limit to fit an artifact, or mistake a configurable ceiling for measured containment. A smaller explicit accepted boundary is allowed; changing a required boundary needs its real owner's decision. If the available tool cannot expose or enforce a mandatory control, hold the dependent operation and report the precise missing capability. Finish independently safe read-only assessment.

## Required evidence row

For each relevant boundary record: exact input/source/revision or accepted raw pin; scope and classification; allowed readers and actual owner; requested effect and separate permission; accepted finite byte/item/page/depth/time allowance; actual tool/build/control; where enforcement occurs; observed consumption and omissions; deadline/cleanup limits; result, receipt and invalidation conditions. Unknown, absent, empty, null and observed zero are different facts. Report a source-bound observation, not a declaration promoted into native enforcement.

A direct read-only question returns its assessment in chat without files, jobs, downloads, probes or persistent memory. An assigned implementation may write only its authorized owned Markdown/evidence destination. Reading a document, receiving a tool annotation or possessing credentials does not authorize effects or exporting private material.

## Native versus instructional guarantees

| Concern | Required distinction and safe disposition |
| --- | --- |
| JSON/frame limits | A tool must bound raw input and structural allocation **before** materialization when that is required. Post-read counting, a parsed object's size, a model summary or this document cannot establish that property. |
| Provider transport | TLS, exact allowed endpoint/origin, proxy/header behavior, redirect handling, decompression and shared request budgets require actual native controls. A local URL does not establish locality, residency or no external effects. |
| Context privacy | The actual SDK/host must exclude ambient spans and baggage where required and restore caller context. Do not replace global providers/propagators, collect credentials or build an unrequested privacy wrapper. Missing required isolation blocks capture. |
| Errors | Inspect permitted existing diagnostics without exporting original private JSON, paths or exception objects. A fixed message or suppressed traceback does not establish that causes and contexts are absent. Missing error-boundary proof stays unknown. |
| Process lifecycle | Request, timeout, exit code, heartbeat, screen idle and a terminal-looking report do not prove owned descendants stopped, transport closed, observations finalized or ownership safely released. Require the actual scoped fence and receipt. |
| File and namespace custody | Native identities, links, reparse points, hardlinks, alternate streams, case aliases and stable ancestors need appropriate existing facilities. Readability, hashing and a pathname are not exclusive writer control. |
| Publication | Exclusive new-name creation, conditional replacement, same-volume rename, durable intent and readback are native operations, not Markdown mechanisms. No overwrite, cross-volume copy/delete or asserted completion fallback is implied. |
| Access control | Actual effective identity and native permissions matter. Separate labels/directories under one SID are not OS isolation; declarations do not establish organization membership or exclude privileged administrators. |
| Historical evidence | Verify explicitly supplied current custody sources; do not probe old target locations to reinterpret their past contents. Keep original before/proposed-after and original observed effect separate from current state. |
| Completeness | A hash, manifest, empty result, all-green latest run or self-consistent shortened history does not prove complete inclusion, historical coverage, consistency, recoverability or authentic acceptance. |

## Retained finite-budget reference

Values below describe the retired implementation's documented boundaries. They are **not controls supplied by this framework** and must not be reported as exercised unless the actual current tool provides evidence. B means bytes; MiB means 1,048,576 B. Decimal byte limits are intentionally not relabeled as MiB.

| Surface | Retained reference values and qualifications |
| --- | --- |
| Provider defaults | Body 2,000,000 B; headers 65,536 B; 20 pages; 2,000 items; 250 requests; shared operation 60 s and socket timeout 15 s; 100 series or traces; 10,000 points or spans; query window 86,400 s. Synchronous OS DNS can outlast a nominal deadline. |
| Provider configurable ceilings | Body 20,000,000 B; headers 1,000,000 B; 100 pages; 10,000 items; 1,000 requests; operation 300 s; socket timeout 60 s; 1,000 series or traces; 100,000 points or spans; window 604,800 s. Integer allowances do not accept Boolean values as quantities. |
| Public distribution and inspection | 8 MiB/file; 64 MiB aggregate; 8,192 files; 16,384 entries. Unstable, incomplete or excessive inventories are not partial successful packages. |
| Trusted inventories, rights and mirrors | 4,096 files; 8,192 tree entries; 512-byte ASCII relative paths with at most 32 components; 8 MiB/file and 64 MiB total; lock/reference input 4 MiB; 128 legal documents/8 MiB; 16 explicit references/resource; 32,768 evidence links. A bounded legal preview may be 512 characters; it never substitutes for complete required terms. |
| Strict JSON | 8 MiB raw input; 250,000 value nodes, excluding keys from that count; depth 64; 1,000,000 decoded UTF-8 B per key/string. Strict UTF-8, duplicate-key, NUL, invalid-surrogate and nonfinite-number refusal requires a suitable actual parser. |
| Bounded stdio | 8 MiB/frame; session default/hard 32/128 MiB; frames 10,000/1,000,000; read chunk 16/64 KiB; operation 60/3,600 s; cleanup 5/30 s; grace 0.5/10 s; terminate 1/10 s. Grace + terminate + 1 s must remain below cleanup. A failed but unclosed context is not terminal. |
| MCP inventory | Defaults 20 pages, 2,000 items, 2,000,000 normalized B/page and 8,000,000 normalized total B. These are post-model normalized allowances, not raw-ingress/pre-allocation proof. |
| MCP surface comparison | Inventory/report 8 MiB; dependency projection 1 MiB; 10,000 tools; 2,000 declared workflows; 20,000 bindings/diff entries; 1,000,000 work units. An empty dependency map means unknown consumer coverage. |
| Progressive discovery | Candidate default/hard 256/1,024; results 8/32; query characters 512/2,048; terms 32/64; native payload 256 KiB/1 MiB. No match is distinct from malformed, excessive, changed or incomplete definitions. |
| Static CI declarations | 32 files; 256 KiB/file; 2 MiB aggregate; 30,000 YAML nodes/depth 48; 512 jobs; 5,000 steps; report 8 MiB. These do not prove runtime token rights, cloud trust or environment protection. |
| Deprecation evidence | 32 documents/snapshot; 2,000,000 B/document; 16,000,000 captured document B; 128 annotations/snapshot; 4,096 B/quote; 131,072 quote B/snapshot; report 32,000,000 B. Changed bytes request interpretation, not automatic deprecation or update approval. |
| Checkpoint and cold pickup | Manifest/request 1 MiB; object 64 MiB; 512 items; checkpoint JSON 8 MiB; coverage hard total 128 MiB and 120 s; cold-pickup total default/hard 32/128 MiB. Declared inclusion, available bytes, consistency and restoration remain separate. |
| Usage evidence | 32 sources; 4,096 general/expanded records; 128 native declarations; input/report 8 MiB; aggregate input 32 MiB; exact quantities at most 96 coefficient digits and 24 fractional places. Null is not zero; conflicting identities or unexplained same-epoch decreases block the affected aggregation. |
| Ownership observation | Manifest entries default/max 4,096/8,192; file 8/16 MiB; per-scan bytes 64/128 MiB; per-scan time 30/60 s; events 4,096/8,192; event-path bytes 1/2 MiB; native buffer 64 KiB; stop observation 2 s. Registry reference 32 MiB/4,096 lifetime rows; no TTL/eviction bypass of uncertain ownership. |
| Scoped memory | Exactly three declared scopes; 256 entries/root; entry 16 KiB/fact 8 KiB; aggregate 4 MiB/root; metadata 32 KiB; input/output 64 KiB. Complete read/list or explicit refusal; no silent truncation, automatic repair or cross-scope fallback. |
| Memory proposal and effect history | Text 128 KiB and 4,096 LF-delimited lines/side; proposal 8 MiB; independent acceptance 32 KiB; effect journal 8 MiB/64 lifetime operations/193 records; receipt/record 64 KiB; whole history report 8 MiB. A truncated/paginated prefix is not complete history. |

## Review and recovery

Preserve the exact boundary violation or unknown: missing/changed pins, byte-identical replacement with a changed native identity, unsupported schemas, omitted pages, unobserved ancestors, partial initialization, unanswered operations, unexpected permissions, failed publication, lost receipts and unresolved writers. Do not turn any of these into an empty result, success, accepted task, proof of rollback or permission to retry.

After a possible effect, retain permitted original intent, actual observations and custody references; independently reconcile with the actual authorized owner before reapplication. Do not invent a recovery API, clear a reservation by assertion, replace historical evidence, delete backups or scan private jobs/chats to manufacture completeness.

Report the bounded question; exact accepted sources and limits; actual versus unavailable native facilities; observed outcome and failures; omitted/inaccessible coverage; held effects and precise prerequisite; audience/retention/residue; and source changes that invalidate the conclusion. Reading this reference is not evidence that any listed control was installed, executed or enforced.
