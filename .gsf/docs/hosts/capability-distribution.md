# Local capability discovery and offline distribution

GSF core is Markdown-only. Discovery, selection, comparison, review and custody below are complete manual/agent procedures over explicitly authorized public sources, using the host's **already available, authorized** read/search/metadata/hash/copy controls. They supply no catalog executable, generator, wrapper runtime, installation, registry contact or permission grant. No extra repository or dependencies are required or authorized. A direct read-only question returns evidence/proposals in chat and creates no files, jobs or host registrations. Actual copying requires an explicit request naming the new external destination; see [plugin export](plugin-export.md).

Bind the approved source identity, exact public roots, owner, data scope, finite bounds and requested output first. Never scan HOME, personal profiles, private jobs/logs/models, chats or history. [Source classification and safety prerequisites](plugin-export.md#1-bind-the-request-and-classify-public-source) apply before reading bytes: complete public source capture, private exclusions, safe local paths/ancestors, link/hardlink/alias rejection, stable operator ownership and real evidence ACLs. Do not modify an unrelated dirty checkout. Unavailable native enumeration, identity, parsing, hashing, no-replace publication or custody controls block their dependent actual effects. Finish a precise honest proposal without claiming unobserved native guarantees.

## Find a local procedure

1. Resolve the complete reviewed canonical root with source `README.md` and classified public `.gsf/` distribution; a partial copy is not silently accepted as core. Inspect only authorized public skill and role entries. Canonical skill identity is `.gsf/skills/<name>/SKILL.md`; role identity is immediate `.gsf/agents/<name>.md`, excluding `WORKER_CONTRACT.md`. Read actual frontmatter and five-pillar Role paragraphs, not guessed descriptions. Apply safe strict metadata parsing when required; missing parser is a named prerequisite.
2. Give each approved source a distinct label and record its actual root, asserted revision/version and observed raw-byte identity. For each capability retain source-local ID (`skill:<name>` or `agent:<name>`), a source-qualified identity formed from **label + kind + exact relative path**, kind, canonical name/description, path and actual SHA-256 when available. The qualified identity distinguishes same-name resources; it is not a host command or a prescribed serialization/API. If a historical qualified ID is used, preserve its literal value and provenance. Never invent a hash to complete a card.
3. Read each domain pack's actual `Kind | Entry | Selection rationale` rows. Record real `packs` membership: known empty membership is `[]`, unknown non-core membership is `null`; `all` means every canonical identity, not a hardcoded release count. Contextual links and names do not add membership.
4. Build the evidence card below for every discovered entry. Retain full-source one-based line ranges, excerpt truncation and exact source identity. Bounded excerpts support navigation, **not** full procedure execution. Read the complete canonical source, prerequisites, effects and referenced authority before recommending use or acting.
5. Report total and facets over the complete accepted source catalog, then matched results separately. An unfinished enumeration is explicitly incomplete and cannot establish absence, total coverage or no collisions. No static skill count is a release truth.

| Card field | Required evidence / unknown boundary |
| --- | --- |
| Identity | Source label/root/revision, qualified ID, source-local ID, kind, name, path, actual wrapper/source digest and observation time; wrapper identity and canonical target identity are distinct. |
| Description | Actual scalar description or first Role paragraph; `description_evidence` includes path, one-based range, bounded excerpt and truncation flag. Do not derive an outcome from a name. |
| `use_when`, `not_use_when` | Existing matching source headings and excerpts, heading name, body-relative heading line and full-source excerpt start/end; absent evidence is `unknown`, not unrestricted suitability. |
| `prerequisites`, plural `effects` | Actual matching source prose. An Inputs heading is input evidence, not proof every input is unconditional. Absent/excerpted evidence cannot establish complete prerequisites or harmlessness. |
| `outcome` | `documented` only for actual description/use-when evidence, otherwise `unknown`; prose, not an inferred outcome taxonomy or promised result. |
| `domain` | `canonical` with actual domain-pack values, including known-empty; `unknown` for non-core roots. No topic inference. |
| Singular `tool`, `effect`, `environment` | Explicit caller-reviewed, exact-source-bound labels only, otherwise `unknown` with reason. Plural source `effects` prose does not automatically become a singular facet. |
| Use / not-use decision | Read-full-source decision, applicable scope and prerequisites, effects/tools actually available and authorized, incompatibilities, known semantic loss and unresolved facts. Discovery is not approval, installation, compatibility or execution. |

For reproducible lexical search, lowercase the query into distinct alphanumeric AND terms; every term must appear in a name, description, actual pack membership or bounded heading excerpt. Per term use its highest matching weight: name 40, description 10, pack 4, excerpt 1. Sum terms and sort descending score, then name, kind, source label and path. Empty query returns all otherwise matching entries with score zero. Limit query text to 512 characters. This is a manual search rule, not a native semantic search tool, embedding service, full-body search or suitability analysis. Record when your existing search tool cannot reproduce that ranking rather than asserting it did.

## Filter outcomes and reviewed facets

Apply all requested filters with AND; retain unfiltered totals/facets separately. Outcome text uses the same distinct AND terms **only** against bounded documented description/use-when evidence, must contain a term, is at most 512 characters and does not change query ranking. Text beyond a reported truncation boundary is not searched by that filter. Domain values are actual `api`, `data`, `cloud`, `interface`, or explicit `unknown`; pack selection and domain filtering may both be applied without inventing a taxonomy.

Core has no exhaustive structured tool/effect/environment annotations. To make one of those facets known, the caller must explicitly review the **full exact canonical source** and supply a version-bound annotation. No implicit sidecar lookup, name heuristic, host probe or permission inference. The following are annotation **contract fields**, retained inside approved Markdown/chat evidence unless a separate artifact is requested; they are not an executable API:

| Annotation record | Constraint |
| --- | --- |
| Collection | `format_version: 1.0`, `reviewed: true`, `entries`; reviewed acknowledges the caller, not independent verification. If consuming an existing structured mapping, require exactly these fields and validate every record before filtering. |
| Entry identity | Exactly `source_label`, `path`, `sha256`, `tools`, `effects`, `environments`; exact case-sensitive canonical path at most 512 characters, actual lowercase 64-hex SHA-256 matching the current source. Non-core wrappers and guessed paths are ineligible. |
| Values | Each label array has at most 32 unique lowercase ASCII labels of 1–64 letters/digits/underscore/dot/hyphen, beginning with letter/digit. `unknown` is reserved for filtering missing values, not a reviewed label. Empty arrays mean unknown, not verified absence. |
| Bounds and integrity | At most 8,192 records and 2 MiB for a supplied mapping. Reject duplicate fields/records/values, unknown fields/entries, stale hashes, malformed/non-finite structured values and unsafe paths, including invalid records outside the requested results. |
| Provenance | Mapping/evidence locator and record index, source label/path, actual source digest, review owner/acknowledgement and observation/version. Keep unmapped dimensions unknown. |

Filter tool/effect/environment by exact reviewed labels. `unknown` selects missing annotation values, not no tools, no effects or verified portability. Reviewed labels remain caller assertions: they are not publisher verification, a sandbox, comprehensive effect analysis or execution authority. Re-review on source drift; never simply replace the expected digest.

Report facets over the **whole accepted catalog before result filters**: kind/pack counts, description/use/not-use/prerequisite/effects documented/unknown counts, outcome documented/unknown counts and domain/tool/effect/environment label counts plus unknown counts. Distinguish known-empty canonical membership from unknown. Preserve counting basis and incomplete coverage; do not manufacture exhaustive counts from the shortlist.

## Compare only explicitly authorized scopes

1. Require at least two named, individually approved roots (canonical source may count as one). Labels are unique portable ASCII names of 1–64 characters. Record inspected absolute root and actual filesystem identity. Duplicate normalized roots or the same real directory through aliases are not independent scopes. Unavailable identity controls block a distinct-scope claim.
2. Accept only an explicitly identified supported shape: canonical core; a plugin/local root with immediate `skills/<name>/SKILL.md` and/or direct `agents/<name>.md`; an immediate skill collection; a directory named `agents` with direct role Markdown; or a single skill directory containing `SKILL.md`. Host-specific layouts, such as Copilot `.github/`, need their actual explicitly authorized component roots identified; do not guess another discovery grammar. Arbitrary references, unrelated nested Markdown and unsupported layouts are not capabilities.
3. Validate matching skill name/description and agent filename/frontmatter or canonical Role-paragraph convention. Exclude worker contract as a role. Non-core pack/domain membership remains unknown even when a name resembles core.
4. Group **all complete discovered catalogs before result filtering** by same-name homonyms across sources, including cross-kind names. Preserve every label, root, kind, path, qualified ID and content hash. Equal names are not equivalent behavior; equal bytes are not equal native configuration or grants. Show accompanying filtered results separately.
5. Record effective host `precedence: unknown` unless actual scoped frontend/version/configuration and resolution evidence establishes it. Directory placement, personal/project labels, source ordering, installation and host registration are not precedence proof. Do not resolve a collision by silently deleting a source or renaming accepted canonical roles.

Only the named roots may be inspected. Ancestors are checked solely for path safety, never searched for other catalogs. No HOME scan, implicit personal/project discovery or host probing follows from a collision request. Existing file presence is neither installed discovery nor invocation evidence.

## Produce an offline external shortlist

Use only an explicitly approved **local** catalog or records supplied by the caller. Do not fetch its URLs. Each record requires exactly seven fields; a five-field legacy record does not gain invented publisher/risk facts:

| Field | Required content and bound |
| --- | --- |
| `name` | Nonempty supplied name, at most 128 characters. |
| `url` | Absolute HTTP(S), at most 2,048 characters, no user/password credentials, query string or fragment. Malformed authorities/ports, controls and secret-bearing URLs fail; do not redact-and-fetch. |
| `license` | Nonempty supplied claim at most 256 characters, explicitly unverified. |
| `description` | Nonempty supplied prose at most 4,096 characters. |
| `requirements` | At most 32 nonempty strings of at most 512 characters; empty does not establish completeness. |
| `publisher` | 1–32 nonempty strings at most 512 characters each; explicitly `unknown` when absent, never inferred from URL/name. |
| `risks` | Same bounds as publisher; `unknown` is not verified absence of risk. |

Bound a supplied UTF-8 catalog to 2 MiB and 1,000 records; reject duplicate keys, non-finite structured values, duplicate name/URL records, disallowed controls and secrets. Review **every** record, not only the shortlist. Lowercase distinct alphanumeric AND terms must match supplied name/description/requirements; rank with highest per-term weight name 40, description 10, requirement 1, tie by lowercase name, URL, original record index. Query must contain a term and requested result limit is 1–100 (default 10). If native tooling does not reproduce the ranking, report manual selection and its evidence, not a fictitious automated result.

Return exact supplied claims, requirements, description and catalog record index with `trust: user-supplied, unverified`, `publisher_verified: false`, `risks_verified: false`; compatibility/use/not-use remain unknown unless separately evidenced. This is lexical relevance, not endorsement, legal approval, quality or suitability. No registry contact, download, installation or configuration occurs; `network_accessed: false` is justified only for an actually offline review (local-looking network filesystems must be disclosed), and `installed: false` describes this operation, not every possible prior installation.

## Lock an approved bundle and verify against external trust

A trust lock is an **immutable accepted inventory record**, not a filesystem immutability service. Keep it in a separately trusted approved storage/distribution channel **outside both bundle and mirror** with real ACLs, retention and retrieval. An embedded lock is ordinary covered content, not an automatic anchor. An attacker replacing both expected inventory and bundle can make them agree. SHA-256 proves correspondence, not publisher authenticity, organization approval, licensing or execution.

### Establish the accepted baseline

1. Inspect the actual completed bundle and its exact inventory/closure/exposure; explicitly approve that specific identity. Preserve authentic approver identity/scope/decision separately. Approval of local bytes is not publisher authentication.
2. Record approver-supplied canonical locator and revision literally, preferably immutable. Do not infer Git identity or a publisher signature; mark `source_assertions_only: true` and `publisher_authenticated: false` unless separate real evidence establishes otherwise. Never store secrets in paths or source identifiers.
3. Capture every covered public file's exact case-sensitive relative POSIX path, nonnegative byte length and actual lowercase 64-hex SHA-256, sorted uniquely; include empty files and any bundled receipts/locks as ordinary bytes. Re-inventory to detect observed path/content drift. No normalization, unrecorded file or recursive self-hash. The trust record itself stays external.
4. Retain exclusions as sanitized names/reasons only. For offline custody the fixed private exclusions are repository metadata `.git`/`.hg`/`.svn` wherever encountered and case-insensitive `.gsf/jobs`, `logs`, `bugs`, `products`, `.audit`, `state/models.md`; their contents are never traversed/read/hashed/copied. They cannot be expanded by a caller record to hide unexpected public files. An accidentally private **distribution output** is a blocking finding, not made acceptable by this lock policy.
5. Freeze the record using actual protected custody. Never overwrite an existing accepted lock or use a candidate as its own expected baseline. Missing reliable byte hashing, stable inventory, accepted identity or private custody blocks the corresponding trust/copy claim; an unverified proposal remains useful but is not an accepted lock.

If inspecting an existing version-1 structured lock, preserve its exact five-field contract: `schema_version` integer 1; `source` with exactly `canonical_locator`/`revision`; sorted unique `files` of exactly `path`/`bytes`/`sha256`; sorted `excluded` path/reason records (directory suffix `/`); and `inventory_sha256`. The latter covers the UTF-8 file array with sorted object keys, indentation 2 and one trailing newline, not a signature. Do not fabricate that aggregate digest without an available authorized exact-byte capability. Unknown schema/fields, duplicate keys, nonstandard/non-finite values, unsafe/case-colliding paths, file/directory prefix conflicts or inconsistent inventories block interpretation. A new manually retained Markdown lock may express the same evidence fields without masquerading as that generated format or API.

### Compare accepted or candidate bytes

For accepted-bundle verification, retrieve the separately trusted expected record explicitly, inventory the actual readable public file set twice and compare **all paths, lengths and digests**. Added, missing, renamed, case-renamed, changed or observed-mutating files fail correspondence; empty directories, timestamps, ACLs and permissions are not proven by a file inventory. Do not repair bytes or refresh expected evidence. Quiescent, access-controlled local storage is prerequisite: metadata checks are not an adversarial snapshot.

For read-only update review, keep the old accepted lock and separately supplied candidate source assertions. Capture the separate candidate twice, rejecting observed drift. Report sorted `added`, `removed`, `changed` exact paths, old/new byte length and actual digest, null for a missing side, plus unchanged count. A rename, including case-only, is removal plus addition, not inferred identity. Retain old source, external lock identity/actual digest, old/candidate inventory identity and candidate locator/revision assertions. `matches_trusted_inventory` means paths/bytes agree, not identical asserted source or approval. A comparison completing with changes is not acceptance. Do not copy, install, advance baseline or expose file-body previews; paths/assertions themselves must be nonsecret.

Use finite custody bounds: 4,096 covered files, 8,192 enumerated/validated paths, 512 ASCII-byte relative paths with at most 32 components, 8 MiB per file, 64 MiB inventory bytes, 4 MiB supplied lock/legal-reference input, 2,048 UTF-8 bytes per source locator and 256 per revision. At most 8,192 combined diff change records. These tighter custody bounds do not weaken the source-capture bounds; an otherwise inspectable larger bundle is over this custody profile, not silently truncated. Reject unsafe/nonportable/reserved paths, traversal, absolute/backslash paths, case collisions, symlinks/junctions/reparse points, **hardlinks**, special entries and ambiguous identities/ancestors. Use real bounded raw reads and observed identity/size/time checks; when unavailable, block dependent verification rather than claim them from instructions.

## Keep legal unknowns explicit

After actual correspondence with the external accepted inventory, inventory local case-insensitive LICENSE/LICENCE/NOTICE names and conventional suffixes (for example LICENSE-MIT or NOTICE.txt). Associate them with resources in their directory/descendants as **ancestor-directory evidence only**, not inferred applicability. Preserve exact legal bytes, notices, headers, attributions and modification markings under actual custody. No Internet license search or grant inferred from a filename/SPDX claim.

Explicit references may map an exact trusted inventory resource path to exact trusted legal-document paths, including differently named terms/copying files. Both sides must already be present in the accepted public inventory; no fetch or outside read. Preserve the caller assertion/mapping and approval separately. Reject duplicate/unknown references and over-budget data. Bounds: 128 legal documents / 8 MiB aggregate, at most 16 explicit references per resource and 32,768 reported resource/evidence links; previews at most 512 Unicode characters or unknown/opaque for non-UTF-8. Only previews may be truncated; inventories may not.

For **every resource**, record path, actual digest/length, evidence paths/digests and basis, `evidence-present` or `unknown`, and independently `rights_status: unknown` until authentic scoped rights review establishes a conclusion. Evidence-present is not licensed: even empty, opaque or inapplicable documents are local evidence. `license_grant_inferred: false` and `license_compatibility_certified: false` remain honest boundaries. Determine actual scope, rights holder, grants, adaptation/redistribution permissions, attribution/notice obligations, compatibility and unresolved gaps for the intended use. Unknown neither grants rights nor automatically prohibits/allows mirroring; required unresolved rights block that dependent distribution. Do not invent a license or organization approval to finish.

Resource kinds are **path heuristics only**, not rights or execution permission. Preserve source assets/legal dependencies in the review map even when the Markdown-only output cannot copy them. Use the following ordered basis if classification is requested:

1. Conventional LICENSE/LICENCE/NOTICE/COPYING/COPYRIGHT/TERMS/PATENTS names and suffixes, or legal/licenses/licences/notices directory: `legal`, even for opaque bytes.
2. Exact `.gitignore`, `.gitattributes`, `.editorconfig`, `.env`, `.npmrc`: `config` (classification does not authorize reading private `.env`).
3. Recognized extension families: `instructions` for md/markdown/rst/adoc/txt; `scripts` for Python/JS/TS/shell/PowerShell/batch/Ruby/Perl/PHP/Lua/R; `fonts` for woff/woff2/ttf/otf/eot; `assets` for image/audio/video/PDF/archive/tabular/binary/wasm/style/HTML; `config` for JSON/JSONC/YAML/TOML/INI/CFG/CONF/XML/properties/env/lock. Record the actual extension and rule, not content-execution claims.
4. Otherwise instructions/prompts directory gives `instructions`, then config/configs/settings gives `config`; otherwise `unknown`.

A script classified in a third-party inventory stays inert. It is not renamed into Markdown or included as an executable GSF dependency. Missing approved assets or their legal closure remain explicit blockers to the affected proposal; do not erase them from the dependency map.

## Offline mirror, receipts and recovery

Only on explicit copying authority, verify the source bundle against the **external accepted inventory**, retain exact frozen covered bytes, and use available native exclusive creation into a new owned sibling staging area. Verify every staged public path/length/digest, re-inventory source for observed drift and publish only with an actually available safe no-replace primitive. Existing destinations, including empty ones or a concurrently appearing target, must remain untouched. Missing no-replace, ownership, reliable identity or stable-source controls blocks publication; no shell recipe or prose supplies atomicity. No repository creation, URL fetching or host installation.

The mirror contains exactly covered public files, without injecting a receipt/lock or private excluded content; recreate only required parents. Keep the trust anchor and copy receipt outside the mirror. Transfer the anchor through its independently trusted channel and compare the received public paths/bytes again at the destination before use. File inventory equality does not preserve ACLs, timestamps, empty directories or native activation. Record actual storage transport, custody, actor/time, source/mirror identity, original failures and complete/partial state; do not claim offline transport merely because the path looked local.

On interruption reconcile only captured owned staging/output and current source identity before another attempt. Preserve original failures, exact expected baseline and partial receipts; never repair source or overwrite expected evidence to obtain agreement. Delete only separately authorized owned temporary material after retained evidence is retrievable under real ACL/retention controls. Uncertain registration/session/remote effects need native readback and a named recovery owner; deleting a bundle is not removal proof. No successful inspection, comparison or mirror establishes publisher authentication, rights approval, installed discovery, invocation or product qualification.
