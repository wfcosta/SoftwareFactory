# Authorized compatibility and upgrades

GSF has no updater executable, dependency installer, legacy-root alias or automatic migration. Use the actual repository-root `.gsf/GSF_CONFIG.md`; never search for a root policy fallback. Preserve product settings, legal notices, required code/security review and deny-by-default publish/merge/deploy. [Installation](../guide/README.md), [host discovery](../hosts/README.md) and [operational custody/resume](../operations/README.md) apply before accepting changed instructions.

## Compatibility matrix

Versions here are independent schema identities, not a claim that the host implements a GSF runtime. Read each accepted schema and normative rules, not just its version number.

| Object/surface | New jobs under this distribution | Existing accepted jobs | Failure/upgrade rule |
|---|---|---|---|
| Canonical policy | `version: '2.0.0'`, [config contract](../../state/config-contract.md) | Frozen accepted policy and instruction/schema snapshot, including version-1 jobs | Only policy 2 starts new jobs. Unsupported/malformed versions block; no default insertion or permissive fallback. |
| Candidate | `version: 2`, [candidate contract](../../state/candidate-contract.md), including collection and verification workspace | Frozen version accepted by that job | Do not relabel a v1 candidate as v2 or infer absent fields. New candidate acceptance follows the current contract only for an explicitly accepted current-policy job. |
| Environment | `version: 1`, [environment contract](../../state/environment-contract.md) | Whatever the accepted job actually required under frozen instructions | New typed observations are not a silent retrofit into old gates. Missing required evidence blocks the claim. |
| Release | `version: 1`, [release contract](../../state/release-contract.md) | Frozen accepted release obligations; no invented historical record | Release state transitions need actual lifecycle events/receipts; a migration cannot synthesize deployment success. |
| Event, plan, models | Current [event](../../state/event-contract.md), [plan](../../state/plan-contract.md), [models](../../state/models-contract.md) contracts; their version numbers are not advanced by the policy change | Exact frozen accepted versions/instructions | Validate each object's own version; do not rewrite versions to the policy version. Optional models remain optional. |
| Framework/product profiles | Existing `framework` / `product`; domain procedures compose by impact | Frozen accepted profile/checks/reviewers | Framework verification does not cover product behavior. Do not invent a new profile enum to bypass checks. |
| Cursor | Actual installed editor/CLI version plus advertised tool map in [adapter](../hosts/README.md#cursor-adapter) | Retain prior version evidence; refresh observations only through job rules | No universal minimum release asserted. | Claude Code | Actual installed CLI version, advertised tools and supported permission/dispatch controls in [adapter](../hosts/README.md#claude-code-adapter) | Frozen instruction identity plus current actual host evidence | Rolling docs or an older tool name are not proof of current interface compatibility. |
| Devin hosted/local CLI | Actual exposed build/CLI evidence and separate session tool maps in [adapter](../hosts/README.md#devin-adapter) | Frozen instructions, actual current session identity | No invented hosted version endpoint; unknown required version/capability blocks affected work. |
| Terminal-only | Actual OS/shell/tools; no implied independent review/UI/cloud capability | Same authority limits | Supported for available serial/read-only work, not a substitute for mandatory missing resources. |

## Freeze versus explicit upgrade

Archived and in-flight accepted jobs retain their exact accepted policy, active instruction bytes, schema snapshots, IDs, events and evidence. Reading newer source does not update them. Never mutate their history, create a root-file alias, silently copy current instructions into their active baseline, or treat a newly permissive policy as authority over old work. A host/version change may make resumption impossible; preserve the job and report the exact incompatible requirement instead of weakening it.

The current pre-release source retains policy `2.0.0`, environment `1` and release `1` while additively permitting a required target `region` to be a nonblank string or null. Existing genuine nonnull regional records remain valid without rewriting. This is a semantic host capability, not null-as-unknown compatibility: accepting null requires authentic provider identity observations and indexed provider documentation proving the exact target has no region dimension, plus exact accepted/observed/action-grant binding with explicit nonregional scope. Missing/blank region, unknown regionality, regional-null targets, fabricated providers and invented `global`/`unknown` aliases fail closed. Preserve all account/resource/freshness/evidence/default-deny obligations. Older frozen fixtures, jobs and actual receipts are never reinterpreted under this additive source representation, even if their version number matches; explicit authorized baseline acceptance is still required.

The same source clarification reserves release.md and its unchanged action enum/state graph for environment deployment/apply/rollback/recovery. Artifact-only registry publication instead retains existing publication_intent/publication_receipt events and indexed immutable source/build/provenance/artifact/target/namespace/version/verification dispatch evidence with actual registry receipts. It needs distinct publication authority, not PR/deploy permission, and cannot imply deployment health. An upgrade cannot synthesize past publication receipts or bypass reconciliation/fencing for stale or ambiguous effects.

An upgrade requires an authentic scoped operator action identifying repository, source/target policy and instruction identities, owned paths, intended changes and affected jobs. Generic task text or candidate-authored policy does not self-authorize a relaxation. Pause/fence active writers first. Prefer a separately authorized new schema-2-policy job referencing the frozen predecessor and its disposition, rather than reinterpretation in place. The predecessor is paused/closed under its own accepted lifecycle; source evidence may be cited, but checks/reviews are not carried forward as fresh results without the new job's acceptance rules. If old frozen instructions cannot be retrieved or enforced, that job stays blocked; an operator may authorize a new job, never fabricated historical continuity.

## Read-only dry-run

A dry-run means **no filesystem, host-registration, permission, package, remote or policy writes** and no job creation. Obtain the actual old/current source and accepted policy bytes through authorized read tools; do not scan private history. Report a proposed patch and evidence findings in the response or already-authorized evidence location only when writing there is expressly allowed.

1. Identify the real repository/worktree/root and target installation. Inventory owned `.gsf/` files, active jobs/workers, host registrations and product-owned configuration without overwriting anything. Establish custody/retention for old snapshots before removal or replacement.
2. Compare current accepted policy with the target [schema](../../state/config-contract.md) using an existing strict YAML parser (duplicate rejection, one mapping/document, no unsafe tags) and Draft 2020-12 validator. Read both normative contracts. Missing parser/validator is a precise prerequisite, not passing manual validation. Do not install one during dry-run.
3. Propose `version: '2.0.0'` while preserving known paths/protected globs, base branch, checks, required reviewers and autonomy. Add every required explicit value: `environments` (empty for workspace-only unless real accepted targets are known); `execution_limits` (parallelism, no-progress attempts, elapsed minutes, max_cost as nonnegative integer ISO 4217 minor units or null, currency); `evidence` (store/retention/location); every check's `effect` and `target`. Establish the real currency exponent and meter conversion receipt for a cap; reject unknown/ambiguous currency, incompatible/unobservable conversion and float/nonfinite policy fingerprint inputs. Inspect commands, package lifecycle hooks, nested skills/tools and side effects before classifying; a label is not a sandbox. Do not guess a cloud account, target, command, grant or enforcement meter. Proposed conservative distribution limits are not authority until accepted.
4. Resolve all paths/check cwd/protected globs from repository root, validate safe paths/symlinks/junctions and existing required skills/reviewer capability. Jobs must not overlap source/policy. Confirm framework checks for the framework and actual documented product checks for products; never remove an unavailable check or independent reviewer to get a passing migration.
5. Map exact current host interfaces/version evidence and mandatory capabilities through the adapter. Establish required evidence-store retrieval/ACL/retention and required cost-cap observability. Enumerate unavailable tools/targets, stale identity, unsupported schema, missing snapshots, unknown writer liveness, retention gaps and protected-path/grant needs. Each blocker names the affected action and exact missing prerequisite.
6. Return the exact proposed changes, compatibility decisions per object/job, preserved authority, required authentic approvals and executable acceptance plan. Dry-run ends without claiming policy accepted, environment READY, product checks passed, job resumed or anything deployed.

## Apply with scoped authority

1. Confirm the authentic grant covers the exact protected policy/instruction edits and any proposed relaxation; preserve immutable baseline and grant provenance under the worker contract. Capture owned pre-upgrade bytes/identities in an authorized recoverable location and confirm retrieval. Unknown live writer or unresolved remote effect blocks replacement.
2. Replace only authorized `.gsf/` source from the identified accepted distribution, preserving legal notice. Exclude copied runtime jobs/logs/evidence and personal model preferences; do not delete retained evidence or unrelated application files. Preserve frozen jobs and their accepted snapshots separately from current source. Change optional host registrations only under specific authority and official host documentation; `.gsf/` copying alone registers no slash commands.
3. Write the complete proposed policy with explicit required fields, all publish/merge/deploy permissions false unless authentic separate grants establish accepted exceptions, and a new accepted policy identity. A snapshot hash mismatch or an intervening change requires re-reading and reconciliation, not overwriting the user's newer work.
4. With explicit verification authority, run strict schema and normative validation of the resulting source/policy, actual configured checks, and mandatory independent code/security plus applicable domain/UI/UX reviews on the same candidate. Exercise adverse migration cases in an authorized external fixture: old policy rejected for a new job; old job remains frozen; malformed/duplicate/unsupported policy blocks; absent effect/target blocks; missing required capability/cap or evidence retrieval blocks; root-relative paths remain correct. Framework scenario coverage follows [verify-gsf](../../skills/verify-gsf/SKILL.md); no test app or helper is installed into distribution.
5. Accept only if preserved authority, snapshots, legal notice, safe paths, actual tool versions, typed effects/targets, evidence-store proof and all required checks/reviews are complete. Persist real results, candidate and policy identities through the coordinator. Environment READY is only a prerequisite result, not acceptance of migration or deployment. New jobs use only schema-2 policy; no old-job auto-refresh occurs.

## Failure and recovery

On validation, check, review, retrieval, capability or grant failure, stop the affected upgrade/action and retain exact failed receipts. Do not broaden permissions, lower gates, install missing tools without authorization, alias old roots, refresh historical snapshots or synthesize missing fields. If source/policy was changed, fence writers and restore only the exact authorized owned pre-upgrade files from the verified snapshot under recovery authority; preserve current evidence/history and unrelated intervening edits. Revalidate restored policy using its matching accepted contract before allowing old-job work. If safe restoration is ambiguous, leave the job stopped and report the precise conflict and recovery prerequisite. Changes to source/candidate identity invalidate affected results; a reverted file is not automatic reinstatement of approval.
