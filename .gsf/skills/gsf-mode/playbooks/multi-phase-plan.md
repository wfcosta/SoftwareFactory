### Multi-Phase Plan

**You own the phase breakdown.** Work that spans phases or stacked PRs. This is for when a single task requires multiple sequential phases with verification between them.

1. **Identify the phases.** Break the work into logical phases where each phase produces a verifiable artifact. Examples:
   - Phase 1: Design and approve
   - Phase 2: Implement core
   - Phase 3: Integrate with existing code
   - Phase 4: Deploy and verify
2. **Define phase boundaries.** For each phase, specify:
   - Entry criteria (what must be true before starting)
   - Exit criteria (what must be true before proceeding)
   - Deliverables (what the phase produces)
   - Dependencies (what other phases it depends on)
3. **Create a phase plan.** Document the phases in order with their criteria and deliverables. This is the roadmap.
4. **Execute phase by phase.** Work through each phase sequentially:
   - Verify entry criteria are met
   - Execute the phase work
   - Verify exit criteria are met
   - Commit the phase deliverables
   - Report phase completion
5. **Reassess between phases.** After each phase, ask: does the next phase still make sense given what we learned? If not, adjust the plan.
6. **Handle phase failures.** If a phase fails its exit criteria:
   - Investigate why
   - Fix the phase work
   - Re-verify
   - Don't proceed to the next phase until the current phase passes
7. **Report completion.** When all phases are done, summarize the overall work and verify the final outcome.

**Reply:** phase breakdown, phase plan with criteria, execution status per phase, any plan adjustments, final verification.
