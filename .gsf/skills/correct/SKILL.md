# Correct

Applicability and host-capability boundaries follow [GSF mode](../gsf-mode/SKILL.md), with shared factory policy in the configured worker contract.

Fix recurring mistakes structurally, not just the latest symptom. For a single isolated defect, use gsf-mode's bug-fix playbook.

1. Read relevant corrections, commits, reverts, review comments, and agent instructions from this task/repository. Group actual mistakes by root cause; a repeated class needs two observed occurrences. Do not mine unrelated private chats or invent repetition.
2. Select the most harmful authorized classes. Record each occurrence's actual receipt/source, the consumer-visible invariant, harmed actor and risk. Use [verification-strategy](../verification-strategy/SKILL.md) and accepted task-matrix rows in `decision.md`/`spec.md` to select the smallest sufficient proof with a real fixture/environment, limitations and exact evidence/invalidation dependencies. No source-text assertion, mock echo or forwarding test proves prevention.
3. Try architecture first in the authorized product: one state owner, one supported path, inaccessible internals, derived rather than hand-synchronized lists. Delete obsolete supported paths rather than adding compatibility aliases. GSF source stays Markdown-only; describe or configure existing host/product/platform controls through their actual supported interfaces, never bundle a helper, test application, runtime or dependency.
4. If architecture cannot prevent it, use actual product types, then an existing lint/check or platform rule whose error names the supported fix. Verify where the rule executes and whether bypasses remain: required CI status/branch protection, API/IAM restriction, transaction/constraint, tool permission or accepted host control must be observed, not inferred from a Markdown sentence. Preserve all applicable required checks/reviews and protected-path/autonomy gates. An advisory check is not a blocking server control. For legacy violations a genuinely supported new-case baseline may be scoped with recorded coverage, never blanket suppressed.
5. Use a behavioral regression when the class cannot be excluded structurally. It must invoke real behavior, fail on an actual past mistake and survive valid implementation changes. Select unit/integration/consumer/journey/property/concurrency/load/formal by risk, not all universally. If no authorized enforceable control exists, report **control absent** with the exact missing host/product prerequisite, residual exposure, owner and manually applied review/check procedure. Documentation can guide judgment but cannot be advertised as enforcement, automatic prevention, sandbox or guaranteed recurrence removal.
6. Prove the chosen control against the observed mistake in an owned external scratch fixture or authorized product scratch worktree, never GSF distribution. Record actual tool/version, command/cwd or skill receipt, candidate/policy/config/build/fixture/environment identity and readiness. Classify configured `effect`/`target` including nested setup/cleanup; external writes/destruction require authentic scoped authority and real target safeguards. Reproduce the past bad operation, capture actual rejection/failure, remove only the owned mutation, then capture the corrected path passing. For a platform guard test the guard itself (for example actual denied unprivileged operation), not merely local lint. Never claim CI/platform rejection without observing it. Missing required capability/authorization/observer means BLOCKED, not a substitute mock success.
7. Update the existing authorized agent instruction rule table with class, two observed occurrences, invariant, control location/owner, enforced versus advisory versus absent status, exact rerun recipe, bypasses/limitations, dependent evidence and invalidation triggers. Remove redundant prose only when the observed control really excludes the mistake. Exceptions need scope, reason, expiry and authentic operator authorization; they do not silently remove a mandatory gate.
8. Retain sanitized failure/success receipts under configured evidence store/location/retention and exact index. Actually retrieve content/digest with authorized identity; record ACL/retention/expiry observations (manual local retention is manual), repeat after owned teardown/cold resume, and keep missing/expired/denied/tampered proof blocked. Apply verification-strategy invalidation to source/policy/instruction, control/config/toolchain/fixture/environment/target/expiry changes. Reuse only with exact immutable dependency/provenance equality and retrieval proof, labeled reused. Clean only owned resources and preserve evidence; unknown-live attempts require reconciliation/fencing before retry.

Report each observed class, broken invariant/risk, actual control and enforcement level, why higher levels were unavailable, failing/passing proof or precise BLOCKED/absent-control prerequisite, newly executed versus reused/unrun evidence, residual bypasses, retention/retrieval and cleanup. A useful manual procedure may be complete documentation while structural prevention remains honestly unavailable. Do not claim automatic monitoring, scheduler, installation or recurrence guarantee from Markdown.
