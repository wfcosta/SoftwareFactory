# Technical Writing

Produce technical documentation following the Diátaxis framework: tutorials, how-to guides, explanations, and reference. Plus Google's technical writing style guide principles.

## Diátaxis Framework

### Tutorials
- Learning-oriented
- Lesson-style
- Hands-on
- Step-by-step
- Goal: acquire a skill
- Example: "Getting Started with GSF"

### How-to Guides
- Problem-oriented
- Recipe-style
- Practical
- Step-by-step
- Goal: solve a specific problem
- Example: "How to debug a failing build"

### Explanations
- Understanding-oriented
- Discussion-style
- Context and background
- Goal: understand a concept
- Example: "How GSF's orchestrator works"

### Reference
- Information-oriented
- Description-style
- Structured
- Goal: look up information
- Example: "GSF skill API reference"

## Google Style Principles

### Structure
- Start with the main point
- Use active voice
- Write for your audience
- Be concise
- Use simple words

### Clarity
- Avoid jargon
- Define terms on first use
- Use examples
- Use diagrams when helpful
- Link to related content

### Tone
- Be direct
- Avoid hedging
- Use "you" to address the reader
- Be inclusive

### Mechanics
- Use sentence case for headings
- Use consistent terminology
- Check spelling and grammar
- Format code blocks correctly

## Process

1. **Identify the document type.** Is this a tutorial, how-to, explanation, or reference? Or a mix?

2. **Structure according to type.**
   - Tutorial: learning objectives, prerequisites, step-by-step, what you learned
   - How-to: problem statement, prerequisites, steps, troubleshooting
   - Explanation: what, why, how, examples, related concepts
   - Reference: overview, parameters, examples, see also

3. **Write in Google style.** Active voice, concise, clear, direct.

4. **Add navigation.** Table of contents, links to related docs, breadcrumb navigation.

5. **Review against audience.** Is this appropriate for the intended reader? Adjust technical depth accordingly.

## Output

Well-structured technical documentation that is easy to navigate, clear, and appropriate for its audience.

## Notes

Not every document needs all four Diátaxis types. Choose the types that fit your content. A README might be part tutorial, part reference. An RFC might be part explanation, part reference.
