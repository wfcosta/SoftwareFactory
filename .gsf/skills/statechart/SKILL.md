# Statechart

Applicability and host-capability boundaries follow [GSF mode](../gsf-mode/SKILL.md), with shared factory policy in the configured worker contract.

This is a Markdown procedure, not a bundled executable, installer, extractor or renderer. Consume an already installed checker or an existing authorized extractor through its documented interface. A graph is not proof; an extractor without a checker cannot establish an invariant. Follow [host discovery](../../docs/hosts/README.md) and [evidence custody](../../docs/operations/README.md), without installing tools or weakening required resources to make the result pass.

## Inputs

Read the actual spec/config, modeled code and candidate identity, the reader's question, named invariants/liveness obligations, constants/bounds and abstraction assumptions. Identify an existing authorized scratch/verification workspace outside distribution source and its accepted effects/limits; no helper, generated model, test product, installer or renderer is added to `.gsf/`. A read-only request may consume existing receipts/graphs but must not create a model or run a checker that writes state.

Build a correspondence table: model variable/state/action, actual code path and candidate-bound lines/symbols, guard, update/atomicity, concurrent interleavings, user-visible behavior and excluded assumptions. Each action points to code or an explicit design assumption. If no existing model exists, authoring one in authorized external scratch is a separate required local-write step, not something the word statechart authorizes. Record immutable input digests and ownership before execution.

## Check

1. Discover the installed checker/extractor, actual path/version, documented usage and output format. For TLC discover a Java runtime and verified `tla2tools.jar` origin/digest; inspect that distribution's help before selecting options. With actual discovered paths, the standard check is `java -cp <absolute-jar-path> tlc2.TLC -workers 1 -config <actual-config-path> <actual-spec-path>`, executed from the authorized scratch cwd. The angle-bracket operands must be replaced by real paths, not executed literally. Record Java/checker versions and exact command. An existing non-TLC checker/extractor uses its own actual documented command; never invent a universal GSF CLI or silently install/download a jar.
2. Define `Init`, `Next` and named invariants. `Next` should be a disjunction of named actions so traces identify transitions. Preserve atomicity and concurrency from the actual implementation, not an easier serial model. Terminal states may stutter with `UNCHANGED vars`; do not disable deadlock checks just to hide a stuck state. State which fairness assumptions and temporal properties are actually checked, not merely written.
3. Freeze constants, initial states, state/action constraints, bounds, symmetry/view reductions and excluded paths. Record checker limits, seed/strategy/workers where relevant and elapsed/resource limits. State constraints may hide deadlocks outside the explored boundary; reductions require a reason they preserve the named property. A finite bounded pass is not proof for all sizes, all inputs or all code.
4. Execute only with verification authority. Retain raw command/cwd, version/help receipts, exact spec/config bytes/digests, stdout/stderr, exit status, actual completion marker, explored/distinct-state and transition counts where the tool reports them, invariant outcomes, deadlock/liveness outcomes and full counterexample traces. Unsupported counts are unknown, not zero. Save raw versus sanitized-retained digests distinctly; evidence references identify bytes actually retrievable. Timeout, tool failure, resource exhaustion, truncated/missing output or incomplete exploration is INCONCLUSIVE, never a passing check.
5. Obtain the actual graph using the installed checker's documented graph-export option/format, or consume an existing extractor's graph and its command/version/input/output receipts. Inspect installed help to choose real export flags; do not guess flags, run a bundled wrapper or install a renderer. Preserve graph bytes/digest, node/edge label semantics, reachability, completeness marker and known omitted transitions. If the extractor uses code rather than checker output, record its actual code candidate/input identities and whether its graph is syntactic, observed or exhaustive within stated bounds. Validate that graph states/actions and property outcomes correspond to the same frozen inputs/run. A partial graph remains partial even when rendered neatly.
6. A graph-only extraction permits descriptive state mapping, not a verified-invariant claim. If checking is required and no checker exists, BLOCKED; if a checked/explored graph is required and no graph export/existing extractor can provide one, BLOCKED for that graph claim. Existing complete receipts may be consumed read-only only if exact candidate, model, bounds and properties still match. A failed invariant is a finding, not permission to weaken it.
7. TLC may stop at its first violation. Mark unexamined properties unchecked; check them independently only in a separately recorded scratch config without hiding the original failure. Use breadth-first exploration for a shortest reported counterexample only when the actual tool/strategy establishes this; otherwise describe an observed path, not the shortest.

## Draw and explain

1. Translate graph states to reader-visible labels and observed/named actions to arrows; emit Mermaid `stateDiagram-v2` text directly, with no renderer dependency. Distinguish a design diagram, a sampled runtime graph, a partial extraction and the complete reachable graph of the **bounded model**. Include node/edge-to-raw-graph correspondence and every abstraction/transition hidden for readability; never label a hand-authored diagram an exported graph.
2. Keep counterexample states distinct. Do not merge states violating different rules; an abstract aggregate containing bad and good concrete states is not uniformly broken. Explain initial/terminal states, guards, updates and stuttering in user terms without changing their semantics.
3. For every violation, name the invariant, user harm and action-by-action trace with actual code correspondence. Replay through available real code/test evidence under separate authority. A non-replayable model step is a correspondence finding requiring explanation/model repair and a fresh check, not permission to alter code or the property merely to force a pass.
4. Deliver the diagram plus graph/model/config/candidate digests, version and raw/retained receipt locators, exact rerun command/cwd, bounds/reductions/assumptions, per-property outcomes and unverified behavior. Report CHECKED only for properties with completed actual checker evidence; EXTRACTED/DESCRIPTIVE for graph-only analysis; COUNTEREXAMPLE for a real violation; INCONCLUSIVE for incomplete runs; BLOCKED for missing required resources. These labels summarize evidence, never approve a product or replace mandatory reviews.

## Failure handling and cleanup

Preserve failed commands, early-stop traces and missing-capability details. Notify the coordinator of affected proof obligations; do not retry unchanged prerequisites, fabricate raw output or claim exhaustive code proof. Quota/resource failure follows the [checkpoint runbook](../../docs/operations/README.md#actual-quota-tool-failure-or-limit-checkpoint); no automatic wake is implied.

Stop owned checker/extractor processes with real acknowledgements; unknown liveness blocks conflicting work. Before deleting authorized scratch, promote necessary immutable model/config/graph/raw-retained receipts to the accepted store, verify retrieval/digests/ACL/retention, and confirm the source candidate stayed unchanged. Remove only owned temporary state/output under cleanup authority, never source inputs, another worker's files or the sole retained counterexample. Record residual processes/files or unavailable cleanup as explicit blockers.
