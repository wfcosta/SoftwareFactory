# Referenced skill protection

## 1. Role

Protect consumers by **refusing unresolved withdrawal** of exact skill source, paths or availability. Build a complete bounded dependency/preservation assessment and an exact change-or-no-change handoff. This is an agent decision procedure, not an OS delete interceptor, reference daemon, scheduler fence, archive executor or global registry.

Use when an owner proposes to remove, relocate or stop distributing/selecting one exact optional skill and its assets. [Skill archive proposal](../skill-archive-proposal/SKILL.md) owns the withdrawal recommendation and return rationale; this procedure checks the actual consumer-preservation preconditions. [Skill curation authority](../skill-curation-authority/SKILL.md) owns authentic jurisdiction; [create skill](../create-skill/SKILL.md) owns separately assigned skill authoring. Ordinary skill selection and unrelated worktree archival are not source-withdrawal authority.

Follow [GSF mode](../gsf-mode/SKILL.md), the configured [worker contract](../../agents/WORKER_CONTRACT.md), [candidate/evidence contract](../../state/candidate-contract.md), [project memory](../project-memory/SKILL.md), [context and memory operations](../../docs/operations/context-memory.md) and configured response conventions. Retain their authority, evidence, ownership, recovery and gates; introduce no new role, canonical state, model key, external JSON API or mandatory gate.

## 2. Context

Select **read-only reference assessment**, **whole withdrawal/preservation proposal**, or **handoff of an already authentically accepted effect**. A direct no-write request returns only a response. An authorized dispatch may write only its already assigned owned Markdown report. Loading this skill does not authorize scanning private records, collecting history, archiving bytes or changing a catalog/source/installation.

Require finite explicit inputs:

- Exact source repository/worktree and optional canonical skill directory, revision, effective local/customized bytes and asset/notices inventory; exact intended effect and owner-approved catalog/pack/distribution/installation surfaces.
- Authentic complete namespace approval for **all actual consumer roots** in the affected domain, including configured external roots, project declarations, distribution evidence and authorized active/paused/frozen/archived/retained consumer references. A directory list is not proof no undisclosed consumers exist.
- Permitted exact read roots and existing nonsecret evidence. Private jobs/logs/history remain out of bounds unless explicitly authorized for that exact assessment; if required consumer evidence is inaccessible, block withdrawal rather than scan it anyway.
- Authentic source, catalog, consumer, rights and custody owners; separate proposal/review/acceptance/effect authority and actual native owner/tool/procedure for any requested later mutation.
- Exact accepted frozen-contract/extraction evidence for historical consumers, actual current liveness/ownership observations and native writer/admission exclusion evidence where effects are contemplated.
- Existing retained-byte/restore evidence, proposed approved archive destination and return route, real readers/writers/retention owner and separately authorized report destination.
- Finite root/node/file/byte/depth/elapsed bounds. Default proposed ceilings: 32 roots, 32,768 entries, 8 MiB per file, 128 MiB aggregate raw bytes, depth 64 and 120 seconds cooperative work. Agree actual bounds before reading; exhausted coverage blocks withdrawal, never produces a no-consumers result.

Use only existing authorized readers, actual raw-byte digest/identity evidence and supported source/reference semantics. No imports, commands, installers, exports, model/provider calls, runtime probes or old companion invocation are needed for discovery. Missing native observations remain UNKNOWN; do not invent a bundled executor, registry or parser for unknown frozen contracts.

## 3. Task

### A. Freeze the actual inventory boundary

1. Bind exact skill/source/catalog identities and effective local changes, not just upstream revision, name or mutable tag. Enumerate every authorized affected source/asset/dependency node and actual approved consumer root within accepted bounds, including directories and empty roots where coverage matters. Record native identity/type, exact path, raw byte count/digest, relevant modes/metadata and original source revision with method/time.
2. Account for every approved root and each actual discovered file/directory. An omitted root, unreadable node, unsupported type/name, alias/case collision, unsafe link/junction/reparse/hardlink/stream, unstable identity or budget gap blocks complete inventory. Do not silently exclude ignored/generated/non-distribution material when it may contain references.
3. Independently establish that approved consumer roots cover the actual domain, including external configuration and retained snapshots. An empty list or zero search hits means only what was explicitly assessed. No HOME/account discovery or machine-wide search can prove absence of undisclosed consumers.
4. Keep source presence, catalog recommendation, canonical discovery, selected wrapper/pack export, installed host activation and upstream publication separate. Removing an index row does not remove canonical discovery or installed bytes; a source move does not disable every host. State each contemplated action and untouched surface independently.

### B. Map direct, transitive and frozen consumers

5. Build an incoming/outgoing reference map to stable closure over the approved inventory. Resolve from exact referring file/version, not a name match. Include Markdown inline/reference/image/HTML links and fragments, directory references, relative assets/templates, wrappers/aliases, canonical catalogs, pack membership/selection and source-to-export closure.
6. Include configured roles, mandatory/optional checks, project runbooks/configuration, direct/transitive instructions, external declared consumers and immutable content-addressed/hash references. Resolve hash references to actual pinned bytes and paths. A retained copy with matching bytes does not automatically preserve an accepted original path or its resume semantics.
7. Treat every authorized active, paused, frozen, archived, failed, abandoned and retained-snapshot consumer as potentially dependent. Status/low use/old timestamps do not prove no consumers, no live writers or no future resume. Distinguish current liveness evidence from a status label; UNKNOWN liveness blocks overlapping withdrawal.
8. For every frozen record require the exact accepted contract and raw frozen bytes, authentic complete extraction evidence and source-to-edge mapping for that exact version. Do not parse it using today's schema, infer an empty edge set from unsupported prose or fabricate an extractor acceptance. Unsupported frozen contracts, unknown dynamic resolution or incomplete extraction blocks withdrawal.
9. Map every discovered edge with this report-local structure; these are prose fields, not a new registry schema:

| Referrer / exact version + raw pin | Consumer root / owner / status and current liveness | Relationship and direct/transitive chain | Exact target path / byte pin / asset or hash resolution | Frozen contract + authentic extraction basis | Preservation or exact proposed migration / unresolved gap |
| --- | --- | --- | --- | --- | --- |
| Actual observed source, catalog, pack, role, check or consumer | Approved boundary, owner evidence and UNKNOWN where needed | Include all intermediate nodes, not only leaf skill | No same-name substitution; preserve path and bytes separately | Exact historical evidence, or not applicable with basis | Remains reachable unchanged, separately accepted future migration, or withdrawal BLOCKED |

10. Account for each inventory node/edge as resolved/preserved or a precisely identified unknown. Missing assets, inaccessible consumer evidence, unsupported contract, unresolved dynamic/content-addressed references, mandatory/public dependencies or omitted roots block affected withdrawal. Never delete a role/check/reference or relabel a requirement optional to manufacture an unreferenced skill.

### C. Specify the whole planned patch and recoverable archive

11. Preserve every accepted frozen consumer's exact bytes, instruction/schema/policy baseline, path pins, assets and immutable reports. Keeping a source URL, hash or archive label is insufficient. If the old path would disappear, withdrawal is blocked unless its actual owner separately accepts a supported migration preserving required behavior; never rewrite frozen history or silently update pins.
12. Describe the **whole** planned reference/catalog/pack patch against exact observed baselines: every affected path/section and complete before/after change, no ellipses or implied cleanup. Include proposed consumer migrations only as separately owned/accepted future changes, not accomplished facts. If no exact baseline is available, keep that surface unchanged and block its patch rather than invent text.
13. Inventory exact recoverable bytes: full skill subtree, relative assets/dependencies, empty directories where relevant, notices/licenses/attributions, local customizations, link targets/modes and required native metadata. Bind each original path to actual retained object/version/path and trusted raw digest, owner, real access controls and retention window. A hash-only manifest, pointer or promise to capture later is not an archive.
14. Inspect already authorized actual retrieval evidence and separately authorized restore-to-new-owned-target receipts where required. Compare complete restored bytes/paths/assets and supported metadata to the accepted inventory. Archive listing or digest metadata alone is not restore proof. Do not perform extraction/copy/restore under read-only authority, use live uncaptured source as a recovery substitute or run restored code.
15. Provide an exact **return mapping**: original and retained canonical paths/bytes/pins; dependency/asset routes; original catalog/pack/role/check entries; exact inverse patch; actual decision/effect owners and native supported procedure; current rights/custody/consumer/capability revalidation needed. Reconcile intervening edits before any return, never overwrite them. Catalog return, source restore, host enablement and republication remain separate actions.
16. Distinguish historical recoverability from current host consumption or successful job resume. An archive receipt cannot prove native discovery precedence, supported installation, usable tools or resumed-job success. Keep each unobserved dimension UNKNOWN.

### D. Refuse or hand off through the actual native owner

17. Apply the refusal rule before any withdrawal handoff: unresolved references, incomplete approved-root coverage, unsupported frozen semantics, unknown liveness/ownership, unpreserved paths/bytes, missing authentic acceptance/rights or missing recoverable bytes/return route means **do not withdraw**. Return a complete blocked proposal with precise prerequisites; low use and a complete-looking table cannot waive this rule.
18. If all review prerequisites are genuinely established and a later effect is requested, identify the actual separately authorized native source/catalog/custody owner and supported operation. Require current action-specific write authority, protected-path compliance, actual stable private ancestors and genuine exclusion of every source/reference/admission writer throughout compare/effect/readback. Existing coordinators do not participate merely because a Markdown procedure mentions a lock.
19. Immediately before that separately owned effect, require the actual owner to reobserve and compare the entire accepted source/consumer/evidence boundary, original versions/pins and supported native preconditions under exclusion. Missing native conditional/exclusion capability or drift blocks effect; no cooperative promise becomes universal CAS or OS isolation.
20. Use existing durable intent, expected prior receipt/head, deduplication and recovery only where the real owner/protocol provides them. Pending intent, lost/partial receipt, replaced custody, ambiguous prior effect or unknown writers blocks new operations too. A new ID, new archive path or new tracking backend cannot bypass ambiguity. Do not create a registry, ledger, database or guard daemon.
21. Require an actual native effect receipt with independent whole-byte/path/metadata archive readback, remaining reference/catalog validity and exact preserved consumer evidence before reporting success. Native rename and receipt persistence are not one guaranteed crash-atomic transaction. Absent real evidence, report handoff only, not archived, removed, protected by OS or safe to resume.

## 4. Constraints and recovery

- This procedure directs an agent to refuse unsafe withdrawal; it cannot intercept arbitrary OS edits/deletes, fence same-user code, automatically lock Core admission or protect against privileged actors. Real ACL/IAM/filesystem/manager controls enforce their actual supported boundaries. Markdown enforces none.
- Keep rights, notices, local customizations, frozen jobs and mandatory checks intact. Do not suppress a finding or remove an obligation merely to simplify withdrawal. Matching hashes establish bytes, not rights, approval or complete extraction.
- No source/catalog/consumer patch, archive capture/move, tombstone, install/disable, publication or deletion occurs under assessment authority. Each needs its exact existing owner procedure and independent approval. No executable script, disguised Python, new runtime dependency or external JSON service is supplied.
- Unknown private consumer evidence is a withdrawal blocker, not permission to inspect private records. Retain private source/rights/custody evidence only in authorized custody and return sanitized references without mislabeling them full original evidence.
- Crash, partial move, missing receipt or failed readback requires the existing owner's reconciliation of actual source/archive/consumer state. Preserve bytes and intent; do not blindly retry, reverse a move, synthesize completion, delete staging/custody, steal locks or claim rollback. Unknown effects remain unknown.
- Changes to source/assets, consumer roots, references, frozen contracts, ownership/liveness, rights, accepted patch, native controls or archive retention invalidate affected conclusions. Finish independently safe mapping; do not silently shrink coverage to call withdrawal ready.

## 5. Format and acceptance

Return **REFERENCED SKILL PRESERVATION ASSESSMENT** with: exact requested effect and identities; authentic finite root/namespace approval and inventory; complete direct/transitive/asset/hash/catalog/pack/role/check/frozen-consumer map; whole conditional patch or explicit unchanged surfaces; exact retained-byte/archive/retrieval/restore evidence and return/inverse mapping; authentic separate owners/rights/decisions; current native preconditions and limitations; explicit withdrawal refusal or qualified handoff; existing recovery prerequisite/owner; actual writes/effects and unexercised observations.

Assessment completeness requires every accepted input, root, edge and preservation/recovery criterion accounted for. Withdrawal readiness additionally requires no unresolved mandatory coverage, authority, liveness, native-control or recovery prerequisite. A complete blocked report is not successful withdrawal or an installed native guard. Use existing report/stop classes and only actual observed evidence.

Decision examples: a paused consumer's transitive asset/path pin blocks source relocation even when usage is zero; an archived consumer with an unsupported frozen contract also blocks. A genuinely complete unreferenced optional-skill map with real retained bytes and exact return patch may support separate owner consideration, but missing writer exclusion still blocks effect. These are refusal criteria, not executed proofs. Manual consumer exercise and independent review require separate assignment and honest receipts.
