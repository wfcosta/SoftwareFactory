# Accessibility automation review

## Role

Apply this procedure through the existing [UX](../../agents/reviewer-ux.md) and [UI](../../agents/reviewer-ui.md) reviewers and [inclusive-experience owner](../domain-review/references/inclusive-experience.md). It supplements their accepted review, not a new accessibility authority, engine, reviewer or mandatory gate. Preserve independent code/security, configured checks and applicable i18n/platform review.

Follow [GSF mode](../gsf-mode/SKILL.md), the [worker](../../agents/WORKER_CONTRACT.md), [configuration](../../state/config-contract.md), [candidate](../../state/candidate-contract.md) and [environment](../../state/environment-contract.md) contracts. Direct no-write advice uses existing permitted sources/receipts and returns chat without files, jobs, browser launches or scans. Dispatch writes only owned Markdown evidence. Product source, rules, suppressions and tests remain unchanged; an existing separately authorized native executor owns any actual UI/engine/manual-AT handoff. No scan is run merely to determine whether an engine exists.

## Context

Recover the exact accepted accessibility obligation, not a generic compliance badge:

- Requirement/source revision, applicable standard/version/level and success criteria, task/actor, supported surfaces and finite required state/browser/OS/device/AT/locale rows. Record actual approved exceptions and owner decisions separately; a rule tag is not an exception or a complete criterion assessment.
- Candidate/policy and exact loaded build/configuration, route/story/component and document/frame scope, fixture/role/tenant, viewport/scale/zoom/theme, state and action sequence exposing it. Use [control-ui](../control-ui/SKILL.md), [verification strategy](../verification-strategy/SKILL.md) and [localization review](../localization-review/SKILL.md) for existing surface/identity owners.
- Existing actual engine/product name and version, integration/wrapper and version, actual browser/runtime, supported target technology, installed/advertised versus actually executed capability, authentic run receipt and complete sanitized results. A browser accessibility tree is not an automated audit engine; an HTML engine is not evidence of a native mobile accessibility audit.
- Exact effective rule IDs/tags/options, enabled/disabled/custom rules, include/exclude contexts, frame/shadow-root reachability, unsupported nodes, timeouts and capture limits. Compare intended scope with actual evaluated scope; defaults depend on the engine/version. If the wrapper hides effective configuration or results, record the required missing proof.
- Independent manual keyboard and actual AT operators/tools/versions where assigned, accepted tasks and qualifications, authorized safe actor/fixture, observed output/announcement evidence and limitations. Do not turn an invented screen-reader transcript into a receipt.
- Accepted positive integer bounds for rows, scans/attempts, UI actions, elapsed time and retained bytes; actual cost/collection limits when relevant, read/capture permissions, permitted recipients and accountable retention/reset owners. Include loading, capture, reset, retries and teardown within bounds.

### Public native reference boundary

Sources retrieved 2026-11-09, not evidence that any engine is installed or available here:

- [W3C WAI selecting evaluation tools](https://www.w3.org/WAI/test-evaluate/tools/selecting/), current/unversioned: tools assist evaluation, cannot automatically check all accessibility aspects and may produce false or misleading results; human judgment is required.
- [axe-core API at tag v4.10.3](https://raw.githubusercontent.com/dequelabs/axe-core/v4.10.3/doc/API.md): evaluates rendered content, inactive/hidden regions need activation before analysis, and contexts/options/results affect interpretation. This pinned reference describes that engine release, not every wrapper or the actual installed release. Use approved documentation for the real engine/version; do not inject axe, invent browser APIs or import examples from this document.

Public examples or vendor accuracy claims cannot prove this target's absence of false negatives, full WCAG conformance, native AT behavior or complete crawl/state coverage. Engine access/license, actual native tooling, target-read/capture authority and separate effect grants must already exist; do not install extensions, enroll accounts or acquire paid access.

## Task

1. **Declare evidence stage.** Separate source/rule analysis, retained actual-engine scan review, newly assigned native scan and manual keyboard/AT evidence. Inspect existing authoritative receipts first. Without exact engine/version, actual completed results, loaded artifact or safe approved scope, required scan conclusions are BLOCKED. Finish independent source/coverage analysis without fabricating a scan, a zero-result object or an engine call.
2. **Build the finite obligation map.** For each assigned criterion name required states/actions, whether automated evaluation can support it and the required complementary manual observation. Distinguish all required rows from a selected sample; denominator is the accepted population of rows/criteria, not the number an engine happened to discover. Unknown total coverage remains unknown. No added criteria, new policy threshold or silent omission to obtain green.
3. **Inspect authentic collection scope.** Match run ID/time, candidate/build, engine/integration/browser versions and actual effective rules/options/context. Compare route/frame/shadow-root and rendered-state coverage, excluded selectors, disabled rules, access failures, truncated results and unsupported content. A resolved scan of an empty or wrong document is not the requested scan. Errors, cancellations and timeouts are failed/inconclusive collection, never clean results.
4. **Review each required visible state.** Where a native handoff is separately authorized, the existing executor uses documented actual tools and exposes the accepted menu/dialog/error/loading or other state before its actual scan. Record precondition, action, actual state, scan receipt and readback; scanning the initial closed page cannot cover an unopened dialog. Do not change production state, install an engine or generate a test harness to reach coverage.
5. **Classify findings faithfully.** Preserve native result categories and original finding IDs, rule/check IDs, criterion mapping, affected element/context, severity/impact, expected versus actual behavior and authentic evidence. For axe when actually applicable, distinguish violations, incomplete/manual-review results, passes and inapplicable; these are not interchangeable. Do not flatten incomplete into pass, omit failures by severity, turn counts into a compliance percentage or assume zero violations means every rule ran everywhere.
6. **Challenge false results and coverage.** Review an alleged false positive against the actual target, engine version, accepted criterion and genuine manual evidence, retaining original output, rationale and accountable reviewer. Do not suppress/disable/reclassify it merely to clear a report. Explicitly list false-negative risks: excluded/hidden/unloaded states, cross-origin or unsupported content, rule limitations and meaning/task-dependent requirements. Clean partial output supports only the executed scope; it never proves no false negatives or WCAG certification.
7. **Complete manual obligations honestly.** Review actual keyboard reachability/order, visible focus, dialogs/escape/restoration, error association and retained input where accepted, plus the exact required AT/browser/OS task and observed announcements/operability. Accessibility-tree inspection or automated role/name checking cannot replace a real screen-reader session. Unavailable required operator/AT/device evidence remains BLOCKED even when automation is clean. Never disable an accepted accessibility setting to make an automation tool pass.
8. **Return actionable remediation and reconciliation.** For each demonstrated issue give affected consumers, minimal reproduction, accepted criterion, likely source boundary where evidenced, existing builder owner and observable resolution condition. Reviewers do not edit source/tests or approve their own fixes. Reconcile prior findings by original report/dispatch/ID using current independent same-predicate evidence; original failures and suppression decisions remain visible. Candidate/config/rules/engine/fixture/state/support changes invalidate dependent proof; preserve previous results.

## Constraints

This Markdown supplies no scanner, browser/axe bridge, crawler, parser, new result schema/ledger or native enforcement. Existing native collection needs real tooling, explicit read/capture authority and separate authorization for state-changing interactions. Startup, focus/locale preference changes, form submissions and engine injection can have effects; declare actual effect/target and genuine platform safeguards, not just a read-only label.

Keep report/artifact custody under the existing evidence index: immutable raw receipt and retained derivative locators/digests, source/job/task/dispatch/run identity, time, authorized reader/writer evidence, actual retrieval and retention control or manual owner/deadline. Minimize DOM/text/screenshots and exclude personal data/tokens. Redaction has separate bytes/lineage; inaccessible or expired original proof cannot be replaced by a summary or fabricated digest.

If a UI operation may have committed or an audit tool unexpectedly mutates target content/settings, stop affected work, retain ambiguity and have the existing resource owner obtain authorized readback before retry/recovery. Unknown session liveness blocks overlapping reset/cleanup. Stop only owned sessions; restore only explicitly owned settings/fixtures with separate authority and actual readback, preserving assistive settings and other users' work. Evidence is not disposable cleanup material.

## Format

Use the [response template](../../templates/response-template.md) or no-write chat. Include exact engine/integration/native support versus actual execution; accepted target and bounded state/rule/manual matrix; native categories/findings and false-positive rationale; false-negative/coverage limits; remediation and prior-finding reconciliation; artifact custody; actual effects/readback/cleanup and unrun actions. Product-source modifications are none.

| Assigned criterion/state | Candidate/build/route/scope and engine/rules/options | Expected automated and manual predicates | Actual scan category/receipt and actual keyboard/AT evidence | Coverage limits | MET / NOT_MET / BLOCKED; precise next owner/action |
|---|---|---|---|---|---|

Use the executing role's verdict; no required unrun scan/state/manual task can receive PASS. Demonstrated defects and simultaneous missing proof both remain explicit. BLOCKED names stop class `environment`, `product` or `factory_bug`, exact missing native capability, receipt or intent and existing responsible owner. A bounded review PASS is not accessibility certification, overall gate passage or release authority.

Illustrative parent manual cases, **NOT RUN**:

- Exact engine/version/rules scan an actually opened approved dialog; authentic results plus required independent keyboard/AT evidence support only the corresponding accepted predicates.
- Clean initial-page scan excludes a cross-origin frame and never opens the menu: retain the clean narrow observation; required frame/menu criteria remain BLOCKED, not WCAG-certified.
- Engine returns incomplete and zero violations: preserve incomplete for manual review; do not count it as pass or disable the rule.
- Automated names/roles pass but actual keyboard focus cannot escape a modal: retain the demonstrated UX defect and remediation; clean automation cannot override it. Missing required screen reader remains a separate gap.
