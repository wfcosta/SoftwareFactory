# Session fork review

## Role

Keep an experiment distinct from its parent execution and protect both from accidental shared authority, state and result promotion. Follow the [worker contract](../../agents/WORKER_CONTRACT.md), [candidate](../../state/candidate-contract.md), [environment](../../state/environment-contract.md), [context-packet](../context-packet/SKILL.md), [cold resume](../cold-resume-review/SKILL.md), [checkpoint coverage](../checkpoint-coverage-review/SKILL.md) and [ownership collision](../ownership-collision-review/SKILL.md) procedures. This is not a session backend, launcher, history exporter or fork API implementation.

A direct bounded review uses approved source and returns no-write chat. A dispatch writes only its assigned Markdown response. Fork creation, content disclosure, experiment execution, resource reservation and cleanup are separately authorized effects; reading a parent's conversation does not grant any of them.

## Context

Require one exact accepted experiment question/hypothesis and independent success/refusal predicates; the native product/frontend/client/server builds and actual supported fork contract; exact parent native session/turn and canonical task/dispatch lineage; approved source snapshot/candidate/policy/instructions/environment; explicit permitted context and data audience; current owner/liveness/effects; bounded child budget and existing native isolation/capture/stop/recovery controls.

Use only explicitly supplied approved snapshots or exact authorized native records. Do not scan personal histories, unrelated sessions, HOME, model transcripts, credentials or private factory jobs to locate a parent or fill missing lineage. Parent access and permission to disclose its contents to another session/provider are distinct.

## Task

### 1. Establish what the actual host can do

| Native capability actually established | Honest route |
| --- | --- |
| Exact documented native fork with parent identity and returned new session identity | Eligible for separately authorized fork commissioning under the remaining steps; support still needs exact installed-version evidence. |
| Exact-session resume/continue only | Same-session recovery, not a fork; route to cold resume and preserve current owner/effects. |
| New independent task/session with explicitly supplied context | A new experiment from approved material, not proof of native inherited state or a historical session fork. |
| Git branch/worktree or copied files only | Code/storage separation, not conversation fork or external-resource isolation. |
| Unknown/unsupported native fork or ambiguous parent | Finish the bounded review and block native fork creation with the precise contract/identity/tool prerequisite; no fabricated API or wrapper. |

Inspect existing advertised schemas and approved version-bound native help/documents only. Do not launch a model, export history, create a service, install a client or call a similarly named method to discover support. Host handles are transport references, not canonical lifecycle IDs.

### 2. Freeze and minimize the source boundary

1. Bind the exact parent snapshot/turn, source revision, full mandatory instructions and original experiment question, with independently accepted identity and actual original-versus-derived byte provenance. A mutable latest conversation pointer or matching title is insufficient.
2. Inventory precisely which messages, files, facts, artifacts, tool definitions, configuration and pending operations the native fork includes/excludes. Native fork semantics may not copy all state; absent complete source/contract blocks a whole-parent-copy claim.
3. Preserve all accepted criteria, blockers, ownership, grants as historical qualifications, original failures and unresolved effects. Do not inherit those grants as child authority or treat parent's completed review as proof for a changed experimental candidate.
4. Exclude secret values, private reasoning, unrelated histories and unapproved recipients. Any authorized sanitized subset is a separately identified derivative, not an exact full fork. Missing required disclosure rights blocks that transfer; no silent redaction presented as byte identity.
5. Reconcile parent owner/liveness and pending effects before giving a child overlapping resources. A fork does not cancel its parent, reset budgets or make uncertain remote effects safe to replay.

### 3. Commission an independently bounded experiment

1. The existing coordinator defines fresh canonical child task/dispatch identity where required and a report-local native parent/child lineage mapping. Keep genuine returned native IDs separate; never reuse the parent's dispatch, forge a fork ID or create a new canonical lineage schema.
2. Supply authentic current child-specific purpose, tool/effect/target, read/disclosure/write limits, owner, expiry and human-approval boundaries. Parent permissions, chat defaults and provider credentials are not implicit child grants.
3. Bind existing real capacity and disjoint file/database/queue/port/browser/memory/effect namespaces; worktree or new session alone is not isolation. Missing required controls blocks dependent execution. Do not create a repository, provision resources, copy accounts or take over a parent's lease as fallback.
4. Fix the experimental factor, exact shared and varied inputs, model/deployment/reasoning/runtime, finite attempts/elapsed/no-progress/cost limits and independently expected outcomes before observing results. Preserve aggregate parent/child expenditure and pending exposure; splitting sessions never resets an accepted cap.
5. Persist the existing assignment/native intent before a separately authorized native fork. Invoke the already supported interface once with exact parent/turn and accepted options. Retain actual acknowledgment/new-session identity and independently read back lineage, inherited inputs and effective child configuration through approved native controls.
6. If no actual fork receipt/readback exists, leave fork outcome unknown. A new task or copied prompt cannot be renamed into a successful fork. Reconcile exact original native intent before retry, rather than creating another child.

### 4. Observe the child without promoting its authority

Capture actual child placement, complete source loading, tool/approval/effect/result/usage evidence and source/retention scope. Keep parent's observations, child native terminality, assigned worker report/done and coordinator acceptance separate. Similar answers or process exit do not prove controlled comparison, source fidelity or safety.

Compare only the accepted independent predicates at the pinned baselines; include failed/interrupted attempts and missing evidence. Uncontrolled shared caches/memory, changed model/configuration, stale resources or incomplete lineage qualify/block dependent causal claims. Do not make the parent repeat an effect or silently refresh its instructions to align with the experiment.

Experimental findings are proposals. Applying a child's source/configuration/memory change to the parent, replacing a parent result, publishing, merging, deploying or migrating frozen consumers requires separate existing owner decisions and current proof. Preserve contrary evidence and the original parent state; never call a favorable experiment automatic adoption.

### 5. Stop and recover the exact owned scope

On interruption preserve original parent/child IDs, acknowledged input, partial writes, budgets and uncertain effects. Use actual same-instance stop/fence/readback controls under [cancellation confirmation](../cancellation-confirmation/SKILL.md); a closed tab, terminal result, deleted local note or disconnected session does not prove remote work stopped.

Retain evidence before separately authorized cleanup of only disposable child-owned state after verified stopped ownership. Do not reset/delete the parent's history, kill shared services, clear grants, overwrite user changes, erase comparison failures or reclaim uncertain resources. If lineage, liveness, custody or external effects remain unknown, block overlapping retry/transfer and name the actual native/resource/evidence owner.

## Constraints

No native session fork, sandbox, identity attestation, budget enforcement, copying right or exactly-once creation is supplied by Markdown. No new runtime/backend/bridge, credentials, model/provider calls, private-history discovery, repository creation or implicit parent mutation. Preserve existing mandatory reviews/protections and frozen snapshots. Changed source/turn/contract/configuration/model/grant/resource identity invalidates affected proof; a new baseline needs authentic acceptance, not a renamed old result.

## Format

Return the [assigned response](../../templates/response-template.md) or no-write chat: accepted hypothesis/predicates and exact native capability qualification; original parent/source identities and complete inclusion/exclusion/provenance map; authentic child authority/budgets/resources; genuine native lineage/commission/readback or NOT RUN/UNKNOWN; per-criterion source/predicate/actual evidence/MET–NOT_MET–BLOCKED; child observations/comparison limits and separate adoption status; actual cleanup/retention/uncertain-effect receipts, owner and next safe action.

Illustrative cases, NOT RUN: an interface that starts blank independent workers supports a new assigned experiment, not a native historical fork. A resumed parent remains the same session. A real fork sharing the parent's database or auto-memory is not isolated; unknown original side effects forbid overlapping replay. A better child answer does not authorize replacing the parent's accepted report.
