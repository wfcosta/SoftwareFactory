# Capability budget routing

## Role

Assess which already existing route, if any, satisfies an exact accepted task without changing its semantics or exceeding current authority/budget. This is an agent decision and existing-native-owner handoff, not a dynamic router, model selector runtime, compatibility bridge, credential broker or permission to switch the assistant's own model/provider. A preferred route in Markdown is not effective routing.

Follow the [worker contract](../../agents/WORKER_CONTRACT.md), [configuration](../../state/config-contract.md), [environment](../../state/environment-contract.md) and [candidate/evidence](../../state/candidate-contract.md) contracts. Reuse [provider evidence review](../provider-evidence-review/SKILL.md), [data residency review](../data-residency-review/SKILL.md), [usage evidence review](../usage-evidence-review/SKILL.md), [budget admission control](../budget-admission-control/SKILL.md), [progressive tool discovery](../progressive-tool-discovery/SKILL.md) and [scheduled job commissioning](../scheduled-job-commissioning/SKILL.md) for their separate obligations. Do not create a routing gate, canonical route registry, model key or policy override.

Direct questions read only permitted retained evidence and return no-write chat without files, jobs, calls or live capability discovery. Dispatch writes only its assigned owned Markdown report. Native route configuration/admission/execution are distinct effects requiring the existing executor, separate authentic authority, actual supported tools and real receipts. This review performs none.

## Context

Freeze the exact task/acceptance source and required output semantics, permitted data/purpose/audience, candidate/policy/environment, actor/owner, actual existing application/client/tool versions, and finite caller-approved candidate routes. Do not enumerate accounts, inspect HOME/private settings/history, look up credentials or call a model to discover routes. A route not supplied by the accepted existing inventory is unavailable for this decision, not a reason to install or construct one.

For each candidate obtain actual provider/platform/account/tenant, exact native deployment and model identifier/version or applicable immutable binding, API/protocol/client version, gateway/proxy and allowed routing/fallback configuration; entitlement/quota/permission evidence; safe configuration provenance and effective-loading receipts. Identify which dependencies are immutable and which are time-limited aliases. A marketing name, generic provider family, plan badge, installed SDK or the current development assistant's model does not prove native support for this target.

Freeze accepted finite candidate/source/receipt counts, per/total bytes, matrix dimensions, retained output size, review elapsed time and evidence freshness. For proposed execution require bounded inputs/context/output, requests/rounds/attempts, tool effects, concurrency, elapsed time, all charge dimensions/currency and cancellation tail through existing native controls. Reference limits and prose do not install enforcement. Record exact primary documentation URL/version, retrieval time and applicability if used; rolling documentation alone establishes neither tenant entitlement nor effective activation.

## Task

### 1. Separate requirements from advertised features

1. Recover a finite list of exact mandatory native predicates from accepted task clauses. Include applicable modalities/input types, context/output bounds, tool/function/schema semantics, streaming/continuation/history, structured output strictness, native search/deferred-disclosure protocol, reasoning/runtime settings, transport and cancellation, privacy/residency and budget. Optional preferences remain separate; do not infer mandatory features or weaken required ones to obtain a route.
2. Preserve actual semantics rather than feature-name similarity. A text description is not structured native output; eager function schemas are not deferred tool discovery; local JSON is not provider acceptance; an image-to-text approximation does not satisfy a required native modality. Use the version-specific contract, not invented SDK methods/fields, protocol conversions or provider aliases.
3. Define each row's exact observable acceptance predicate and required evidence level. A source-bound design question may be answered from source, while a required effective capability needs applicable actual native receipts. Never call a tutorial, local fixture or another deployment a successful capability observation for this one.

### 2. Compare each existing route against independent evidence

Maintain separate report-local columns for **requested**, **configured**, **advertised**, **resolved effective**, **sent**, **accepted** and **actually exercised** facts. An absent level stays unknown. A successful response does not by itself prove the actual model, full route or feature semantics.

For every candidate:

1. Bind native support to the exact model/deployment/protocol/client/version combination using independently accepted primary documentation plus actual advertised/effective-capability evidence appropriate to the predicate. Generic “and later,” a name prefix or ordinary function support cannot prove client-executed tool search or another distinct capability.
2. Bind the current effective actor/account/tenant, entitlement, exact deployment access, quota dimensions, revocation/expiry and authentic action/data authority. Credentials, a paid plan, a reported approval or available quota do not authorize this request. Do not obtain new credentials, sign up, upgrade a plan or assume credits reset.
3. Resolve configuration precedence and routing dependencies from accepted evidence: winning source/profile, explicit pin versus inherited default, alias revision, wrappers, gateway, proxy, region, override/fallback behavior and actual loading. Unknown resolution blocks dependent execution; a requested model or region is not its effective counterpart.
4. Map code/context, telemetry/usage metadata, audio where applicable, artifacts and stored/backup/support copies using data-residency-review. Bind permitted data/purpose/processing/storage/access/retention to the exact route. A regional endpoint, encrypted request or local gateway does not prove downstream processing/storage geography. Unknown required residency blocks that route, even if its primary endpoint is permitted.
5. Obtain exact current monetary meter/currency/ISO 4217 exponent and source-backed account/rate semantics. Preserve original exact decimal quantities and conservative upward conversion to integer minor units through existing approved exact arithmetic. No binary floats, assumed two-decimal currencies, FX mixing, invented prices or treating credits/tokens/unmetered usage as free money.
6. Bind the complete bounded incremental liability, disjoint current in-flight reservations/liabilities, actual remaining accepted budget and actual compatible native hard-cap/admission controls through budget-admission-control. Expected token cost or a soft quota is not an enforceable monetary bound. Unknown required cost/meter/cap or concurrent exposure blocks dependent execution; this review does not create a reservation or reset counters.
7. Confirm this route is executable by the existing authorized native tool/application, not merely describable. Required tool/interface/cancellation/fencing/receipt capabilities must already exist. Missing capability leaves the route unavailable/unknown; do not create a new router, adapter, service, wrapper or fallback executable.

### 3. Choose without expanding the task or authority

A candidate is eligible only when every mandatory predicate is supported by current applicable evidence, the exact data/action authority is valid, native executable support is established, and current budget admission prerequisites are satisfied. Demonstrated mismatch is NOT_MET; missing/stale/ambiguous/unrun required evidence is BLOCKED. Do not average predicates into a score that hides a hard failure.

Among eligible candidates apply only the accepted finite selection/tie-break policy. Prefer an explicit authorized pin when required; an optional price preference cannot override capability, residency or identity. If multiple candidates remain and no authentic selection rule resolves a material semantic/authority/cost choice, name the exact authorized decision owner rather than self-select a provider. If no candidate is eligible, return no admissible route and complete the safe matrix; do not substitute a cheaper approximate capability or invoke the current assistant's model.

The result identifies one existing route and exact binding, or a dependent block; it does not mutate chat/session defaults, native model settings or scheduled-job revisions. For an automation, preserve the accepted commissioning model/routing revision. A later chat preference, wake, provider outage or quota failure does not change that binding.

### 4. Bind any separately authorized execution to actual route receipts

Hand the existing executor the exact task/input disclosure boundary, selected native route/version, candidate/policy/environment, authority and evidence expiry, mandatory predicates, current budget basis and required receipt/readback fields as review dimensions, not invented native API keys.

Before any separate native effect, its owner must revalidate effective actor/account/deployment/model/protocol/client/configuration, current authority/entitlement, residency, remaining budget, in-flight ownership and actual native cap. Configuration changes require their own scoped authority and receipt. Only the real native request/operation/admission receipts and effective-execution/readback evidence can establish which route was used. Preserve source/task/dispatch/attempt and input/output/artifact identity in existing private-safe evidence; retain unknown hidden downstream routing explicitly.

A requested route differing from the effective receipt is drift, not a successful substitution. Withhold dependent acceptance/effects, preserve the actual response and its real costs, and route the mismatch to its existing owner. Do not silently retry through another provider, model, protocol, fallback gateway or semantic approximation. Any genuinely desired alternative requires an authentic new selection/routing authority, fresh capability/residency/budget evidence and a new binding before execution.

On timeout, quota error, interrupted stream or ambiguous result, reconcile actual operation/liveness, accepted outputs, charges and remote effects before retry. Cancellation request is not observed stop; keep bounded or unknown liabilities under the current owner and follow existing fencing/recovery. A failed result does not erase spend, restore credits or permit overlapping attempts. Retain failed and contrary receipts alongside later decisions, without manufacturing a routing receipt or replaying a potentially completed request.

## Constraints

No commands/probes, model/provider calls, credential lookup, model self-switch, automatic fallback, paid-plan/signup/credit-reset assumption, host enablement, new router/runtime/adapter/parser/schema/ledger/service/repository or executable program hidden in Markdown. No changes to existing canonical models/configuration, shared reports or scheduled tasks under this review. Native limits, enforcement and actual activation remain existing platform responsibilities with separate authority and real proof.

No capability fabrication from labels, documentation alone, local translations or source examples. Preserve required independent reviews and actual evidence retrieval/integrity/ACL/retention. Changes in task semantics, model alias/version, native route, account/entitlement, protocol/client, configuration, data policy, grant, price/meter, native cap or ownership invalidate affected selection immediately. Complete independently safe analysis without promoting required unknowns into optional preferences.

## Format

Use the [assigned response template](../../templates/response-template.md) or no-write chat. Include accepted task/selection policy and finite bounds; authentic authority/owners; exact native candidate identities and requested-to-effective evidence levels; complete capability/protocol/entitlement/residency/budget/executable-interface matrix; chosen existing route or no admissible route; and native handoff/readback/recovery prerequisites.

| Criterion / exact native route | Expected mandatory capability, authority, residency or budget predicate | Actual documentation revision / indexed receipt / evidence level and limits | MET / NOT_MET / BLOCKED | Held dependent action / owner / exact missing prerequisite |
| --- | --- | --- | --- | --- |

Cover every assigned criterion and original finding once, distinguish actual observations/inferences and NOT RUN effects, and use the executing role's actual verdict. Include private-safe immutable evidence locators/raw digests/provenance/retrieval/ACL/retention, native selection versus effective routing/admission/execution distinctions, known/uncertain costs, stop class, modified product files normally `[]` and all unresolved surrounding-operation owners. A review PASS cannot assert a provider call happened or its native feature was activated.

### Manual consumer cases — illustrative, NOT RUN

- **Exact supported route:** supplied current primary/native receipts identify one authorized existing deployment/client with every required predicate, permitted data path, current entitlement and real bounded budget controls. Recommend only that binding for the existing executor; without actual subsequent routing/execution receipts, execution remains NOT RUN.
- **Protocol approximation rejected:** task requires client-executed deferred search, but a cheap route offers ordinary functions only. Eager schema disclosure, a local shortlist or pasted JSON is not equivalent; mark the required capability NOT_MET/unknown as evidenced and do not construct a shim or substitute the current model.
- **Cost or residency unknown:** an advertised capable deployment lacks a monetary meter/hard cap, or its permitted primary region has unknown required telemetry/backup geography. Block dependent execution despite favorable listed price; no unknown becomes zero cost or safe residency.
- **Requested versus effective drift:** request/configuration names route A but a genuine execution receipt identifies B through a gateway/default. Preserve B's actual output/cost, reject the A-effective claim and reconcile under its owner. Do not self-switch, retry to A or present fallback as success.
- **Quota failure and interrupted work:** a pinned scheduled route reaches quota or returns an interrupted response with uncertain remote work. Preserve its commissioning binding and spent/reserved liability, require actual stop/effect reconciliation and renewed authority if needed; do not promise credit resets, buy a plan or automatically choose a different provider.
