# Physical mobile device review

## Role

Use through the existing [platform specialist](../../agents/platform-specialist.md) for its accepted design-readiness or runtime-validation stage, with existing [UI](../../agents/reviewer-ui.md), [UX](../../agents/reviewer-ux.md), [localization](../localization-review/SKILL.md) and [verification strategy](../verification-strategy/SKILL.md) owners as applicable. This is a bounded agent procedure, not a mobile automation driver, device farm, backend, new role or additional mandatory gate. Preserve independent required code/security/checks and each accepted specialist's own verdict.

Follow [GSF mode](../gsf-mode/SKILL.md), the [worker](../../agents/WORKER_CONTRACT.md), [configuration](../../state/config-contract.md), [candidate](../../state/candidate-contract.md) and [environment](../../state/environment-contract.md) contracts. Direct no-write advice uses already authorized sources and retained observations, returning chat without jobs, files, app/device calls or probes. Dispatch writes only owned Markdown evidence. No product code, tests, app, driver, service or executable is created. A real device interaction is a separate explicitly authorized handoff to an existing available native tool/executor; this skill does not enable a host or discover credentials.

## Context

Obtain actual accepted inputs, not an assumed mobile target:

- Requirement revision, consumer/actor task, exact supported platform rows and physical-hardware predicate, stage and prior finding identities. Distinguish native app, mobile browser and embedded webview. A mobile browser on physical hardware may satisfy a mobile-web requirement, never an unexercised native-app requirement.
- Authentic device owner/lab booking and exclusive session scope; actual manufacturer/model, hardware identifier stored privately, physical-device provenance/observation, OS version and build, relevant architecture, screen/density/orientation and locale. A marketing device name or capability request alone does not establish physical hardware or the target actually selected.
- Candidate/policy, exact installed app package/bundle identity, version/build and artifact digest/provenance or accepted immutable binding, signing/distribution identity without secret material, configuration/flags/backend/tenant, actor/fixture and expected starting app/data state. For mobile web record actual browser/version/URL/build; for hybrid record native versus webview context and versions separately.
- Existing documented native driver/tool, client/server/driver/plugin versions where applicable, supported target/commands, actual session ID and returned effective capabilities, device binding and ownership receipt, app launch/readiness and actual run observations. Requested capabilities are intent; returned capabilities and independent actual device/app observations establish the narrower execution claim.
- Current genuine access/entitlement/permission observations for that exact device/session/app, approved account/data/capture scope, existing required signing/trust/developer/automation prerequisites and operator. Availability of credentials or an unlocked personal phone is not permission to use it. Do not copy device serials, account identifiers or pairing/signing secrets into public output.
- Accepted finite state/journey rows and positive integer caps on devices, sessions, actions, attempts, reset operations, elapsed time and artifact bytes; permitted network/data usage and actual monetary cap/source where required. Include setup, capture, retries, state readback and cleanup in limits. Required unobservable budgets block dependent execution.
- Explicit effect/target/grants and real native safeguards for each action class, owned fixtures, allowed permissions/preferences, cancellation/fencing, evidence custody and cleanup/recovery owner. Record starting permissions/preferences/app/data state so approved restoration can be distinguished from blanket reset.

### Public native reference boundary

Primary references retrieved 2026-11-09; these describe possible existing tools, not this host's availability or entitlement:

- [Appium session capabilities](https://appium.io/docs/en/latest/guides/caps/), rolling **latest**, no installed release established: capabilities describe a requested session and are fixed during its lifetime; Appium-specific capabilities are namespaced and driver support is not universal. The documented `appium:udid` identifies a device and `appium:automationName` selects a driver, but supplied values alone prove neither returned identity nor physical hardware. Use the actual installed client/driver version's documentation and receipts; no session JSON or calls are fabricated here.
- [XCUITest device preparation](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/), rolling **latest**, no installed release established: real iOS devices require approved trust/configuration, WDA installation and valid provisioning; the driver may automatically change keyboard preferences. The documented requirements and settings are not permission to install WDA, enable Developer Mode/UI Automation, change accessibility settings or pair a personal device. Existing legitimate device/signing operators must establish required prerequisites separately.

A versioned XCUITest 11.11 device-setup URL returned 404 during research; no 11.11 support claim is derived from it. The rolling preparation reference must be reconciled to the actual approved driver version before any native handoff. No Appium installation/server, device enrollment, paid farm signup or alternative backend is supplied. Other genuine native drivers are usable only with their own approved exact-version documentation and actual receipts; do not invent method names from general platform knowledge.

## Task

1. **Establish stage and feasible surface.** Inspect accepted support promises, runbooks and retained device/session evidence. For design readiness describe the target-specific proof prerequisites without claiming runtime success. Runtime validation requires actual approved physical hardware, native controls, exact app/session identity and safe authority. Missing device, required host OS/tooling/signing, permissions, controls, isolation or receipts yields BLOCKED for the affected row; continue independent permitted source/evidence analysis.
2. **Prove physical identity and ownership.** Match authentic lab/operator inventory/observation to the actual effective session and device binding, avoiding unnecessary private enumeration. Record requested versus observed model/OS/build and physical versus simulator/emulator. Do not accept a cloud label, generic device name, desktop responsive mode or an emulator screenshot as physical-device proof. A real remote device is acceptable only with authentic approved provider/session physical-hardware provenance and scoped access.
3. **Confirm app readiness without unowned setup.** Match the installed artifact/configuration and usable authorized actor to the accepted row; a connected device, running app or open screen alone proves neither exact build nor usable task. Record actual app/process/context and initial permission/data/network state. Inspect documented driver defaults, startup/install/reset/hook effects before any separately authorized native handoff. If it would alter unowned source/device settings, install an app/agent, reset data or trigger backend writes without a grant, stop before creation and name the existing owner action needed.
4. **Freeze finite native journeys.** For each row specify initial state, exact existing documented tool action/input, expected visible and persisted predicate, supporting readback method and stop/reset boundaries. Cover the accepted positive path plus affected adverse/neighboring path such as denied permission, validation, background/foreground, rotation, offline/recovery, keyboard or safe cancel only when authorized and relevant. Do not invent a universal device matrix or expand into notifications/camera/location/biometrics/telephony without explicit scope.
5. **Review or perform separately assigned native interaction.** The existing authorized executor drives the actual chosen physical surface through supported native controls. Retain authentic ordered action receipts, session/context, timestamps, actual visible/accessible results, allowed screenshots/logs and operation identifiers. Record every context switch; webview-only evidence cannot prove native controls or system-permission dialogs. Screenshots alone are not taps, gestures, keyboard/AT sessions or backend persistence. Use actual required TalkBack/VoiceOver or other accepted AT only with genuine assigned operator/tool evidence; a tree dump does not prove spoken output.
6. **Read back real effects and failures.** Compare visible outcome with the accepted independent predicate and authorized app/backend readback. Record permission prompts/decisions and resulting actual state; pregranted permissions do not prove a first-run flow. A native action timeout may have committed. Stop duplicate taps/submissions, retain original intent/session/operation identity and have the current app/resource owner query approved state before another attempt. If readback is unavailable, effect remains unknown and dependent runtime completion/retry is BLOCKED, not a failed action assumed safe to replay.
7. **Reconcile each finding and required row.** Bind original report/dispatch/finding IDs to the exact current device/app/session evidence and original resolution condition. Preserve observed defects and unexercised physical/OS/app/AT rows separately. No emulator, mobile-web, alternate OS or desktop evidence silently substitutes. Different installed artifact, OS build, device/driver, configuration, permissions/fixture or accepted predicate invalidates dependent observations; keep old attempts immutable.
8. **Close owned sessions safely.** Preserve required retrievable evidence before stopping. Use the existing native tool's supported stop/fence mechanism only for the owned session and observe actual termination. Cancellation request is not proof of stop. Read back owned app/fixture/preference changes and separately authorized restoration against the baseline; session deletion alone does not prove device cleanup. Report every residual permission, installed agent/app, artifact, account/fixture, backend effect and owner disposition. Unknown liveness/effects block overlapping retries, reset and destructive teardown.

## Constraints

No fabricated device commands, calls, screenshots, physical hardware, driver behavior or tool receipts. No new backend/wrapper/server, permanent test/suite, app/story code, canonical registry/schema/ledger or automatic enforcement. No SDK/driver/plugin installation, pairing, signing changes, device enrollment, security-setting changes, account creation or entitlement upgrades under this review. Native capabilities and separately scoped authentic authority must already exist; a Markdown decision is not a device lock or host sandbox.

Review source and already retained evidence only unless actual runtime work is explicitly assigned. Match true action effects to accepted targets and grants: launching/capturing can expose private notifications; driver startup may install agents/reset preferences; app navigation can call remote services. A read-labelled assignment cannot hide those writes. Stop affected capture on private data exposure and retain only minimal sanitized discrepancy; never browse photos/messages, private HOME, unrelated apps or shared device history.

Preserve nonowned device settings, accessibility accommodations, apps/accounts, pairing, data, sessions and user work. Never factory-reset, uninstall shared apps/agents, revoke another operator's trust, clear all data/logs or restore global preferences from a guessed baseline. If the driver's mandatory defaults conflict with preserving a nonowned device, runtime is BLOCKED pending legitimate owner-provided suitable target or separately authorized preparation, not an invitation to use it anyway. Recovery/compensation needs its own exact scope and authentic receipts.

Use existing evidence custody: immutable source/session/run identities and locators, raw and sanitized derivative digests/lineage, capture time, retrieval and reader/writer ACL observations, actual retention control or manual responsible owner/deadline. Device artifacts may contain identifiers, tokens, screens and personal data; minimize and redact before permitted retention/disclosure. Preserve independently retrievable bytes beyond teardown; an expiring farm URL, session label or claimed digest without accessible proof cannot satisfy a gate.

## Format

Use the [response template](../../templates/response-template.md) or no-write chat. Include stage, actual physical proof, exact device/OS/app/driver/session/configuration identities privately where necessary, permission and ownership basis, finite matrix/limits/counters, authentic native interaction/visible/persisted receipts, prior-finding reconciliation and unrun obligations. Report product-source modifications as none, actual effects/readback/cleanup, residual ownership and exact missing prerequisites.

| Assigned criterion/row | Physical device/OS build, app/artifact, driver/version and effective session/context | Starting permissions/data, allowed actions and expected predicate | Actual native action, visible result and persisted readback evidence | MET / NOT_MET / BLOCKED; missing proof or defect and existing owner/action |
|---|---|---|---|---|

Use the executing role's stage-specific verdict. Missing required physical/native/AT proof or unresolved effects/ownership is BLOCKED; observed defects use that role's documented failure/CHANGES vocabulary and retain simultaneous blocked rows. State stop class `environment`, `product` or `factory_bug` and precise safe next action. No scoped result certifies all devices, replaces independent UI/UX review or authorizes publication/deployment.

Illustrative parent manual cases, **NOT RUN**:

- Authentic approved physical-device inventory/session receipt matches OS build and installed accepted artifact; real native action and permitted app/backend readback demonstrate the selected task, followed by observed owned-session stop and authorized fixture cleanup. Accept only those rows.
- Desktop mobile emulation or an Android emulator has convincing screenshots: physical requirement remains BLOCKED, even if source/visual evidence is useful.
- XCUITest access exists but starting its agent would modify an operator's nonowned keyboard/accessibility setup or requires unapproved provisioning: no session start/setting change; legitimate device owner must provide approved preparation or an owned suitable device.
- Submit times out after a real tap: no second tap, reset or uninstall. Preserve session/operation evidence and require actual state reconciliation; unknown effects and liveness stay BLOCKED until the current owner supplies proof and separate recovery authority.
